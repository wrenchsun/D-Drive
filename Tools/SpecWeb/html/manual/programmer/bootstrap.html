起動配線（DDriveRuntimeBootstrap）

D-Drive のランタイムは、DDriveRuntimeBootstrap という 1 つの MonoBehaviour が唯一の Composition Root（組み立て場所）です。すべての Manager（AudioManager / VfxManager / AnimManager …）はここで生成され、各静的ファサード（Audio / Vfx / Anim …）へ Bind されます。new AudioManager(...) のようにゲームコード側で Manager を直接 new することはありません。

Manager を new してよいのは 3 箇所だけ: DDriveRuntimeBootstrap・自動テスト・Editor プレビューです。ゲームコードは静的ファサード（Audio.PlaySe(...) など）を呼ぶだけにしてください。

シーンへの配置

メニュー Tools > D-Drive > Generate > 起動オブジェクト(DDriveRuntimeBootstrap)をシーンに配置（実装: Packages/com.ddrive.core/Editor/Bootstrap/BootstrapSceneSetup.cs:17）を実行すると、[D-Drive] Runtime という名前の GameObject が作られ、DDriveRuntimeBootstrap が付きます。同時にプロジェクト内の AssetCatalog（Tests/ 配下を除く）を自動収集して Inspector の Catalogs に設定します。カタログを増やした後は、同じメニューか Inspector の「カタログを再収集」ボタンで更新してください。

シーンに 1 つだけ置いてください（[DisallowMultipleComponent]。2 個目を置いても既存のものが優先され、新しい方は破棄されます）。KeepAcrossScenes（既定 true）が ON の場合、DontDestroyOnLoad でシーンをまたいで生き続けます。

クラス宣言

[DefaultExecutionOrder(-1000)] [RequireComponent(typeof(GameLoopDriver))] [DisallowMultipleComponent] public sealed class DDriveRuntimeBootstrap : MonoBehaviour

DefaultExecutionOrder(-1000) により、シーン内の他のどの Awake() よりも先に実行されます。RequireComponent(typeof(GameLoopDriver)) のとおり、GameLoopDriver（後述）が自動的に一緒に付きます。

呼び出し順（Awake → Start → 破棄）

  1. Awake()（DefaultExecutionOrder(-1000) によりシーン内で最初に実行）
    • Build() がすべての Manager を生成し、GameLoop.Register(...) で GameLoopDriver の Tick ループへ登録する
    • BindFacades（既定 true）が ON なら、Audio.Bind(...) / Vfx.Bind(...) など各静的ファサードへ Bind する
    • ネットワーク（NGO）を使う場合、この時点では 役割の決定・ブリッジの選定・Transport の設定だけを行い、実際の起動は行わない（下記コラム参照）
  2. Start()
    • RegisterCatalogsAsync() を呼び、Inspector の Catalogs と CatalogLabel（Addressables ラベル）からカタログを Registry へ登録する。完了すると IsReady = true・OnReady 発火・WhenReady が完了する
    • NGO を使う場合、保留していた NetworkManager.StartHost() / StartClient() をここで実行する
  3. 破棄時（OnDestroy）: Options.SaveIfDirty() → Teardown()（GameLoop.StopAll → 各 Manager を GameLoop から解除 → 各静的ファサードを Bind(null) で Unbind）の順。
なぜ StartHost/StartClient は Awake ではなく Start まで遅延するのか: NetworkManager.StartHost() / StartClient() は、NetworkManager 自身の Awake() / OnEnable()（内部状態の初期化）が済んでいないと NullReferenceException になります。これは実機確認で発見された問題で、DDriveRuntimeBootstrap は DefaultExecutionOrder(-1000) で他の全オブジェクトの Awake() より先に走るため、Awake() 内から直接呼ぶと NetworkManager がまだ初期化されていません。そのため Awake()（Build() 経由の ResolveNetBridge()）では起動オプションの決定だけを行い、実際の呼び出しは全オブジェクトの Awake() が終わった後の Start() まで遅延させています。

ゲーム側の作法

起動直後は IsReady == false の期間があります。この間に Audio.PlaySe(...) 等を呼んでも例外にはならず、未登録 ID として Placeholder（無音 / マゼンタ球）扱いで継続します。狙った ID できちんと再生させたいコード（タイトル画面の BGM 等、起動直後に鳴らす必要があるもの）は、WhenReady を待ってから呼んでください。

async UniTaskVoid StartAsync()
{
    await DDriveRuntimeBootstrap.Instance.WhenReady;
    Audio.PlayBgm(BGMID.TitleTheme);
}

GameLoopDriver

GameLoopDriver（Packages/com.ddrive.core/Runtime/Loop/GameLoopDriver.cs:8）は、シーン内で唯一の Update() 入口です。各 Manager 自身は Update() を持たず、GameLoop.Tick(dt) 経由で駆動されます。通常、ゲームコードから直接触る必要はありません。

プロパティ型役割
GameLoopGameLoop登録された各 Manager（IAssetManager）へ Tick / Pause 通知 / StopAll をブロードキャストする
TimeServiceTimeServiceHitStop 等を考慮したスケール済み deltaTime を計算する
PauseServicePauseService下記

Update() では、毎フレーム TimeService.Tick(Time.unscaledDeltaTime) → GameLoop.Tick(TimeService.ScaledDeltaTime(...)) の順に呼ばれます。

PauseService

Packages/com.ddrive.core/Foundation/Pause/PauseService.cs:8。チャンネルごとに多重 Push/Pop 可能なスタック式ポーズです。同じチャンネルを 2 回 Push したら Pop も 2 回必要です。

void Push(PauseChannel channel) void Pop(PauseChannel channel) bool IsPaused(PauseChannel channel) bool IsAnyPaused() event Action<PauseChannel, bool> OnPauseChanged
  • 深さが 0→1 になった瞬間に OnPauseChanged(channel, true)、1→0 になった瞬間に OnPauseChanged(channel, false) が発火する（深さが 2 以上のままの Push/Pop では発火しない）
  • 対応する Push の無い Pop は警告ログを出して無視される（例外にはならない）
  • PauseChannel は Gameplay / UI / System の 3 つ

取得は DDriveRuntimeBootstrap.Instance.Loop.PauseService。

Options（音量・UI 速度などの永続設定）

Packages/com.ddrive.core/Runtime/Ui/OptionStore.cs:213 付近の静的ファサード。DDriveRuntimeBootstrap が起動時に PlayerPrefs から読み込み、破棄時 / アプリ終了時に変更があれば自動保存します。

float Get(OptionKey key) void Set(OptionKey key, float value) event Action<OptionKey, float> OnChanged

未 Bind のときの Get は 1f を返します。OnChanged は未 Bind の間に登録しても購読が消えず、後から Bind されたインスタンスへ自動的に付け替わります。

ScenePreload（シーン読み込み時の一括プリロード）

Packages/com.ddrive.core/Runtime/Loading/ScenePreload.cs:11。ロード画面などから、複数 ID をまとめて先読みするための窓口です。

void Bind(IAssetRegistry registry) UniTask RunAsync(ScenePreloadList list, IProgress<float> progress = null) void Release(ScenePreloadList list)

list が null、または未 Bind（起動配線前 / テスト環境）の場合は、progress に 1f を即時報告して即完了扱いになります（例外にはなりません）。Release は RunAsync で確保した参照を解放するために、シーンアンロード時などに対で呼びます。

Addressables とカタログの同期

Packages/com.ddrive.core/Editor/AssetBrowser/AddressablesSync.cs:18 が、Asset Browser で作成した Data アセットとカタログを自動的に Addressables へ登録します。

  • Data アセット: グループ DDrive_GameData に、カタログ上の Address（＝ファイル名）と同じ address で登録
  • カタログ自体: グループ DDrive_Catalogs に、ラベル DDriveCatalog（＝DDriveRuntimeBootstrap.DefaultCatalogLabel）付きで登録。DDriveRuntimeBootstrap.CatalogLabel にこのラベルを設定しておくと、Inspector で直参照していないカタログもこのラベル経由で起動時に自動収集される

ID 定数（SEID / VFXID / ANIMID など）の再生成は Tools > D-Drive > Generate > Regenerate Asset IDs。生成先やコード規約は concepts.html を参照してください。

出力先パスの設定（DDriveProjectSettings、2026-09-20 追加）

Packages/com.ddrive.core/Editor/Settings/DDriveProjectSettings.cs（ScriptableSingleton<DDriveProjectSettings>、ProjectSettings/DDriveProjectSettings.asset に保存）が GameDataRoot / GeneratedRoot / SourceAssetsRoot / SpecsRoot の 4 つの出力先パスを持ちます。既定値は現状の決め打ちパス（Assets/GameData 等）と同じです。

現時点ではこの設定を実際に読みに行くコードはまだありません（AssetCreationService.DefaultGameDataRoot 等の既存の決め打ち定数は変更していません）。持ち込み先が自分のフォルダ構成に合わせて出力先を選べるようにする土台で、実際の参照差し替えとセットアップウィザードは後続チケットで行います。
