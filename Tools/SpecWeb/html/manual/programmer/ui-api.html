Canvas / UI Tween / Skin

UI 画面（Canvas）を開閉する Ui、UI 要素の動き（フェード・スライド・パンチ等）を再生する UiFx、コントロール（ボタン等）の見た目セットを解決する UiSkins の 3 つの静的ファサードを扱います。Canvas アセット・専用エディタの作り方はデザイナーマニュアル: Canvas の設定項目・Canvas Editor の使い方を、UI Tween のデータ形式はUI Tween の設定項目を、Skin はUI Skin の設定項目を先に読んでください。

同期版と Async 版の使い分け

UiManager の実装（Runtime/Canvas/UiManager.cs:307-323）を見ると、Open は Canvas を生成して OpenTransition（演出）を 開始した時点で Handle を返し、OpenAsync は同じ Open を呼んだ上で その開く演出が終わるまで await します（Close / CloseAsync も同様）。

戻るタイミング向いている用途
Open / Popup / Close演出の開始と同時（同期）「開いた/閉じた」という事実だけ必要で、開閉演出の完了を待たずに次の処理へ進みたいとき（大半のケース）
OpenAsync / PopupAsync / CloseAsync開閉演出（CanvasData.OpenTransition / CloseTransition）が完了してから「完全に開き切ってから入力を受け付ける」「閉じ切ってから次の画面を開く」のように演出の完了そのものに依存する処理を続けたいとき
// 開始と同時に次へ進んでよい場合
var h = Ui.Open(CANVASID.Shop);

// 開く演出が終わってから何かしたい場合
var h = await Ui.OpenAsync(CANVASID.Shop);
FocusFirstButton(h);

CloseTop / CloseTopAsync はスタックの一番上（CanvasData.CloseOnBack=true のもの）を閉じます。戻るキー・Android バックボタンの配線に使います。

Signal によるゲームコードとの連携

UI 側の ButtonWire / SliderWire は、ボタンが押された・スライダーの値が変わったときに UiManager.SendSignal を内部から呼びます（Runtime/Canvas/UiManager.cs:1128, 1223）。ゲームコードは Ui.OnSignal(key, cb) で購読するだけで、どの Canvas のどのボタンが押されたかを受け取れます。

// SignalArgs: Key(合図名) / Canvas(発行元Handle) / ElementPath(要素の名前) / Value(SliderWireのときの現在値)
var sub = Ui.OnSignal("shop/buy", args =>
{
    Debug.Log($"{args.ElementPath} から購入シグナル");
});

// 購読解除(Canvasを閉じる/オブジェクト破棄時など)
sub.Dispose();

Ui.OnSignal は R3 の Observable ではなく、IDisposable を返すだけの素の Action<SignalArgs> 購読です（未 Bind のときは何もしない NullDisposable.Instance を返すので、Dispose() はどちらの場合も安全に呼べます）。SendSignal をゲームコードから直接呼んでコード発の合図を送ることもできます（UI 側は購読していれば受け取ります）。

Stop / StopAll の complete を省略すると位置がずれることがあります。 既定の complete: false は Tween を途中の値のまま打ち切ります。SlideIn 系のプリセットは UiPresetFactory.Build の時点で「そのときの anchoredPosition」を静止位置として採用する設計なので、 前の Tween が終わる前に止めて再生し直すと、中断された中途半端な位置が次の静止位置として使われ、 繰り返すたびに本来の位置から離れていきます（2026-09-17 の U-23 の実害）。 同じ要素に対して再生し直す場合は complete: true で止めてください。

アドホック Tween

MoveTo / Scale / Fade / Rotate / MoveAlong は、プリセット化するほどでない一回限りの Tween をその場のパラメータで再生します（UiTweenManager に直接委譲、Ease 引数は省略可）。

Sequence() — 複数 Tween の連結

TweenSequence（Runtime/UiTween/UiFx.cs:150）は「ちょっとした演出シーケンス」を UniTask で連結する薄いビルダーです。定常経路（Tick 等）向けではないため、通常の List/async を使って実装されています。

await UiFx.Sequence()
    .Append(() => UiFx.FadeIn(panel))          // 前の区間が終わってから start を呼んで再生開始(本当の順番再生)
    .Join(() => UiFx.SlideInLeft(icon))         // 直前の区間と同時に再生する
    .AppendInterval(0.2f)                        // 前の区間の完了を待ってから 0.2 秒待機
    .Append(UiFx.PunchScale(button))             // 開始済みの Handle を渡す版。完了の待ち合わせだけ順番になる(見た目は同時)
    .Play();
メソッド意味
Append(Handle)すでに再生中の Handle を渡す。呼んだ時点で再生は始まっているため、順番になるのは完了の待ち合わせだけ
Append(Func<Handle>)前の区間が終わってから start を呼んで再生を始める。本当の意味での順番再生
Join(Handle) / Join(Func<Handle>)直前の Append/Join と同じ区間として同時に再生する
AppendInterval(sec)直前の区間の完了を待ってから UniTask.Delay で待機する
Play()async UniTask。各区間を順番に、区間内は並列に _manager.WaitAsync(handle) で待つ

UiSkins 静的ファサード

Runtime/Ui/UiSkins.cs:9。UiInteractable.SkinId（AssetId<ControlSkinMarker>）の遅延解決だけを行う薄いファサードです。R3 は使わず Func ベースで、DDriveRuntimeBootstrap が起動時に Bind/Unbind します。

public static class UiSkins
{
    public static Func<AssetId<ControlSkinMarker>, ControlSkinData> Resolver { get; }

    public static void Bind(IAssetRegistry registry);
    public static void Bind(Func<AssetId<ControlSkinMarker>, ControlSkinData> resolver);
}

Bind(IAssetRegistry) は registry.TryResolveSync<ControlSkinData>(id.Value, out var skin) を包んだ既定のリゾルバを設定します。テスト等でリゾルバ自体を差し替えたい場合は Bind(Func<...>) を使います。通常のゲームコードから直接呼ぶ場面は少なく、UiInteractable 側が内部で UiSkins.Resolver を参照します。
