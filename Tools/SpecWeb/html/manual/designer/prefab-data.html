Prefab データ(ゲーム中に出す物)の設定と Prefab Editor

最終更新日: 2026-10-13

Prefab データ(PrefabData)は、ギミック・弾・拾い物・背景オブジェクト・キャラクターなど「ゲーム中に出したり消したりする Prefab」を 1 個ずつ登録するデータです。登録しておくと、次のことがすべてデータだけで決まります。

  • どの Prefab を出すか(Prefab)
  • 用途の目安(Kind)と、ゲームの判定に使う目印の文字列(GameplayTags)
  • 出したときに強制するレイヤー(CollisionLayer)
  • 遠くにあるときの簡略表示(LOD)の切り替えタイミング(Lod)
  • 使い回す(プールする)か、同時に何個まで出せるか(Flags の Pool)
  • 出た瞬間・消える瞬間に鳴らす効果音、出すエフェクト(Events)
プログラマーは Prefabs.Spawn(PREFABID.Player, 位置, 向き) と書くだけです(消すときは Prefabs.Despawn(handle))。「出現時に煙と音を出す」ためだけのスクリプトは要りません。ゲーム固有の動き(敵の AI など)は、これまでどおり Prefab 側のコンポーネントに書きます。
モデルデータとの違い: Prefab データには、装備の差し替え(スロット)のような「見た目の切り替え」はありません。見た目を差し替えたいものは モデルデータで作ってください。

対象のデータを選んでいない（空の）ときは、ウィンドウの「サンプルを作る」ボタンでサンプルのデータを作って試せます（Assets/GameData/<種別>/Sample/ にカテゴリ Sample で作られます。同じものが既にあれば、作らずそれを選びます）。

開き方

  1. Asset Browser(Tools > D-Drive > Asset Browser)のツールバー「新規」→「新規アセット作成」ダイアログで、「種別」に Prefab (PrefabData) を選び、「表示名(日本語可)」「カテゴリ」「識別子(英語)」を入れて「作成」。ファイル名・ID・カタログ登録はツールが自動で行います(生成先は Assets/GameData/Prefab/カテゴリ/、ファイル名は PREFAB_カテゴリ_識別子)
  2. Project で Prefab データを選び、Inspector の一番上の「Prefab Editor で開く」を押す
  3. またはメニューバー Tools > D-Drive > Editors > Prefab。Project で Prefab データを選ぶと自動で入ります(「🔒 固定」を ON にすると追従しません)
.prefab ファイルを Asset Browser にドラッグ&ドロップしても何も起きません(ドラッグで作れるのは音源ファイルだけ)。必ず「新規」から作り、あとで Prefab 欄に入れてください。識別子は英語の PascalCase(例: PlayerSlash)で。違う形式だと「識別子は英語 PascalCase(例: PlayerSlash)で入力してください」と出ます。

はじめの一歩(壊せる箱を登録する)

  1. Asset Browser の「新規」で種別 Prefab、表示名「壊せる箱」、識別子 BreakableBox で作成
  2. Inspector の「Prefab Editor で開く」→ 設定の Prefab に箱の Prefab を入れる
  3. Kind を Gimmick、GameplayTags に Destructible を 1 行追加(プログラマーが「壊せるか」を判定する目印になります)
  4. 「確認用シーン」→ 確認用シーンが開き、SceneView の中心あたりに箱が置かれる。「確認する」の欄の状態が「プレビュー配置中」になる
  5. 見た目・大きさ・レイヤーを SceneView / Game ビューで確認。直したら「撤去」→ もう一度「確認用シーン」
  6. 使いたい場面(ID は PREFABID.BreakableBox)をプログラマーに伝える

画面の説明(Prefab Editor)

ウィンドウの中に 3D の絵は出ません。確認は必ず SceneView / Game ビューで行います。プレビューはゲーム実行時とまったく同じ仕組み(PrefabsManager)で出すので、Pool 設定・レイヤーの強制・LOD の上書きもそのまま再現されます。

要素説明
◀ ▶ と名前の欄編集する Prefab データを切り替えます(名前の欄で検索もできます)。Project で別の Prefab データを選ぶと、ウィンドウの中身も切り替わります
🔒 固定ON のあいだは、Project の選択に追従しません
＋ 新規 / Projectその場で新しい Prefab データを作る / Project でこのデータをハイライト
かんたん / 標準 / 詳細出す欄の量(かんたん = Prefab だけ、標準 = よく使う欄まで、詳細 = すべて)。右上の検索で欄の名前・説明からも探せます
確認用シーン確認用シーンを開き、実際のゲームと同じ仕組みで Prefab を出します。Hierarchy に [D-Drive] Prefab Preview が出ますがシーンには保存されません。押すたびに前のプレビューは消えて置き直されます。右クリックで、いま開いているシーンへの配置・本配置も選べます
今のシーンに配置 / 撤去確認用シーンへ移らず、開いているシーン(またはプレハブモード)の SceneView の中心に出す / プレビューを消す。撤去せずにシーンを切り替えても残骸は残りません
Prefab で開くPrefab をプレハブモードで開きます
状態の表示「「確認用シーン」で確認できます」→「● プレビュー配置中(保存されません)」。「配置に失敗しました」が出たらコンソールを確認
固定バー変更の件数・自動保存・保存(Ctrl+S でも保存できます)
エラー・警告は該当する欄の下に出ます(ヒーローの「✕ エラー」「⚠ 警告」のチップでも件数が分かります)。まとめて見るときは Tools > D-Drive > Validation > Run All(Validation の見方)。

設定項目

項目説明
Prefab実際に出す Prefab。未設定でもゲームは止まらず、<Placeholder:PREFAB> という空のオブジェクトが出ます(エディタでは 1 回だけ警告)。本番に出す前には必ず入れてください
Kind用途の目安。Gimmick(ギミック)/ Projectile(弾)/ Pickup(拾い物)/ Environment(背景)/ Character(キャラ)/ Other(その他)。一覧の整理と検証のための分類で、ゲームの判定には使いません(判定は GameplayTags で)
GameplayTagsゲームの判定に使う目印の文字列(例: Destructible)。プログラマーが「このタグを持っているか」で分岐します。大文字小文字まで完全一致なので、綴りはプロジェクト内で揃えてください(似た綴りは検証がタイポとして指摘します)。Asset Browser の検索用「Tags」とは別物です
CollisionLayer出したときに強制するレイヤー番号。-1 = Prefab のレイヤーをそのまま使う。0〜31 = 子オブジェクトまで含めて全部そのレイヤーに変える。Project Settings の Tags & Layers に名前があるレイヤーを指定します
Lod遠くにあるときの簡略表示(LOD)の切り替え位置を、Prefab 側ではなくデータ側で決めたいときに使います。Enabled を ON にして ScreenRelativeTransitionHeights に LOD 0, 1, 2… の切り替え値(0〜1)を、Prefab の LODGroup の段数と同じ数だけ入れます。Prefab に LODGroup が無ければ何もしません
Events出た瞬間(OnSpawn)・消える瞬間(OnDespawn)などに鳴らす効果音・出すエフェクト。使い方は Anim Editor の Events と同じです

共通項目(すべてのデータに共通)

項目説明
Id / Version / Author / UpdatedAtツールが自動で付けます。手で編集しないでください。Id は名前を変えても変わりません
DisplayName / Description / Category / Tags / IconAsset Browser での表示名・説明・フォルダ分け・検索用タグ・アイコン。Tags は TagCatalog から選びます(自由入力は非推奨)
ChangeNote変更内容のメモ(任意)

Flags(使い回し・優先度・ネットワーク)

項目説明
Pool.Kind「プール」= 消したものを捨てずに取っておいて次に使い回す仕組み。None(既定)= 使い回さず、消したら破棄。Pooled = 消したらプールに戻し、次に出すときは同じオブジェクトを再利用。弾・ヒットエフェクトのように短命で数が多いものは Pooled にします(2026-09-11 に実機で動作確認済み)
Pool.InitialCountあらかじめ作っておく数。プログラマーがシーン開始時などに「温め」(PreloadAsync)を呼ぶと、この数だけ先に作られます。Pooled のときだけ効きます
Pool.MaxCount同時に存在できる上限。超えて出そうとすると、Priority が一番低いものが強制的に回収されます。Pooled のときだけ効きます
Priority上限に達したときの残りやすさ。数値が高いほど残ります。Pool が None のときは効きません
Pause / Load / Persistent / DomainPause: ポーズ中の扱い(Prefab 本体はポーズで特別なことをしません)。Load: 読み込みのタイミング(既定 LazyLoad = 最初に使うときに読む)。Persistent: シーンをまたいでも消さないか。Domain: ゲーム内(Game3D)/ UI / 両方
Netマルチプレイでの扱い。Local = 自分の画面だけ。Cosmetic = 見た目だけ全員の画面で出す(結果に影響しないエフェクトなど)。Simulated = 結果に影響するのでサーバーが管理する(弾・ギミック・キャラ)。Simulated は Prefab のルートに NetworkObject が必須です
Pooled のときの目安: 弾なら InitialCount=32、MaxCount=128(検証も同じ値を推奨してきます)。「温め」は Prefabs.PreloadAsync で行ってもらってください。同期版の Preload は、まだ読み込まれていないものを素通りすることがあります。

よくある使い方

やりたいこと設定
壊せる箱Kind=Gimmick、GameplayTags に Destructible。「確認用シーン」で見た目確認
弾を大量に撃つKind=Projectile、Pool.Kind=Pooled、InitialCount=32、MaxCount=128。シーン開始時に温めてもらう
出た瞬間に煙と音Events に OnSpawn の行を足し、SE と VFX を入れる(スクリプト不要)
当たり判定用のレイヤーを強制するCollisionLayer にそのレイヤー番号(子まで全部変わります)
遠景の切り替えタイミングを調整Lod.Enabled を ON、ScreenRelativeTransitionHeights を LODGroup の段数ぶん入れる
拾い物(コイン等)Kind=Pickup、Pool.Kind=Pooled、GameplayTags に Pickup など
マルチ対戦で結果に影響する物Net=Simulated + Prefab に NetworkObject。クライアント側からの Spawn はサーバーへの要求になり、その場には出ません
見た目だけ試すPrefab Editor →「確認用シーン」→ 調整 →「撤去」

よくある警告

Prefab Editor では該当する欄の下に出ます。Tools > D-Drive > Validation > Run All でも一覧に出ます。

表示対処
Prefab が未設定(または Missing)ですPrefab 欄に Prefab を入れる。空のままでも動きますが本番には出せません
CollisionLayer '…' は未定義のレイヤーです(-1=Prefab のレイヤーを維持、0-31=定義済みレイヤー)-1 に戻すか、Project Settings の Tags & Layers に名前のあるレイヤー番号にする
Kind=Projectile ですが Flags.Pool が Pooled ではありません(Pooled(32, 128) を推奨)弾は使い回すのが前提。Pool.Kind=Pooled、InitialCount=32、MaxCount=128 を目安に
Flags.Net=Simulated ですが Prefab に NetworkObject がありません(サーバー権威の複製には NetworkObject が必須です)Prefab のルートに NetworkObject を付けるか、Net を Local / Cosmetic に戻す
Flags.Net=Simulated は Kind=Projectile/Gimmick/Character を想定しています(現在: …)意図的ならそのままで OK(Info)
Flags.Net=Simulated(サーバー権威の複製)と Flags.Pool=Pooled(プール再利用)は併用注意ですネット同期と使い回しの組み合わせはズレの原因になりやすい。どちらかを外すかプログラマーに相談
GameplayTags[i] が空白です空の行を消す
GameplayTags[i] '…' は重複しています同じタグが 2 回。片方を消す
GameplayTags[i] '…' は既知タグ '…' のタイポの可能性があります他の Prefab データで使われているタグと大文字小文字違い・1 文字違い。綴りを揃える

注意点

  • Kind はゲームの判定に使いません。判定は GameplayTags で
  • Pool=None は破棄です。MaxCount / Priority を入れても効きません。使い回したいときは Pooled に
  • Net=Simulated は NetworkObject が必須。また Simulated + Pooled は警告になります
  • Simulated の物はクライアント側では直接出ません(サーバーへの要求だけ)。実際のネットワーク複製は Phase 6 で接続予定です
  • プレビューはシーンに保存されません。保存したい配置は自分でシーンに置いてください
