パッケージを導入する / 更新する

最終更新日: 2026-09-20

D-Drive は「別のプロジェクトへ持ち込めるパッケージ」（com.ddrive.core）として配布されています。このページでは、導入・更新・置き場所の選び方・テストの有効化・困ったときの確認方法という操作の説明だけを紹介します。

導入する

導入はプログラマー・テクニカルアーティストが行うことを想定していますが、流れを知っておくとトラブル時に自分でも状況を確認できます。

  1. パッケージを追加する: プロジェクトの Packages/manifest.json に D-Drive の git URL を 1 行追加する（詳しい書き方はパッケージの README.md を参照）
  2. Unity を開き直す: Package Manager が D-Drive を解決し、依存パッケージの一部を自動で導入する
  3. セットアップウィザードを開く: Tools > D-Drive > Setup > セットアップウィザード
  4. ウィザードの各ステップを上から順に確認し、足りないものを「直す」ボタンで揃える（下記「セットアップウィザードとは」参照）
  5. SE を 1 件登録して試聴し、Play Mode で ID から再生できることを確認する

セットアップウィザードとは

D-Drive を新しいプロジェクトに持ち込んだとき（または D-Drive を更新した後）に、必要な設定が揃っているかをまとめて確認し、足りないものをボタン 1 つで直すための画面です。プログラマー・テクニカルアーティストがプロジェクトの立ち上げ時に使うことを想定していますが、デザイナーが「なぜエフェクトが出ないのか」を確認するときにも使えます。

開き方

  1. Unity のメニューバーから Tools > D-Drive > Setup > セットアップウィザード を開く

確認できること（上から順に）

  1. 依存パッケージ: D-Drive が必要とする外部パッケージ（UniTask・R3 など）がプロジェクトに入っているかを確認し、足りなければ「追加」ボタンで導入する
  2. ProjectSettings: レンダーパイプライン（URP）・入力方式（Input System）・API 互換レベルが D-Drive の前提と合っているかを確認する（自動では変更しない項目もあります）
  3. 置き場所: D-Drive が作るデータ（GameData フォルダ等）をどこに置くか選べる（下記「置き場所の選び方」参照）
  4. 既定フォルダ・設定の生成: 最初に必要なフォルダや設定ファイルをまとめて作る
  5. Addressables 同期: アセット管理の仕組み（Addressables）が初期化されているかを確認する
  6. 起動オブジェクト: ゲームを実際に動かすために必要な「起動オブジェクト」をシーンに置く
  7. テストを有効化する: 下記「テストを有効化する」参照（既定は OFF）
  8. エージェント向けスキル: AI エージェント（Claude Code 等）が D-Drive を正しく使うための手引きを、このプロジェクトの設定にコピーする
  9. 完了チェック: 上のすべての状態を一覧表示し、Validation（自動チェック）もあわせて実行できる

置き場所の選び方

ウィザードの「置き場所」ステップでは、D-Drive が作るデータの置き場所を 3 通りから選べます。

  • 既定のまま: Assets/GameData・Assets/Generated・Assets/SourceAssets 等、Assets 直下にそのまま置く
  • 1 つの親フォルダ配下にまとめる: 指定した 1 つのフォルダ（例 Assets/_Project/DDrive）の下にまとめて置く。プロジェクトに「Assets 直下に新しいフォルダを作らない」という規約がある場合はこちらを選ぶ
  • 個別に指定する: フォルダごとに個別の場所を指定する

すでにデータがある状態で置き場所を変更しても、既存のデータは自動では移動しません。新規作成分だけが新しい場所に作られます。

テストを有効化する

D-Drive 自身が持つテスト（EditMode/PlayMode）を、このプロジェクトの Test Runner で実行できるようにするかどうかの設定です。既定は OFF（実行できない状態）で、通常のゲーム開発では ON にする必要はありません。プロジェクトの CI に D-Drive の自動テストも含めたい場合にだけ ON にします。ウィザードと更新ウィンドウのどちらからでも切り替えられます。

更新する

Tools > D-Drive > Update > 更新ウィンドウ を開きます。

  1. 更新チェック: 「最新の版を確認」を押すと、公開されているバージョンの一覧を取得し、現在使っている版と比べて「最新です」「MINOR の更新があります」「MAJOR の更新があります」を表示します。MAJOR の更新は先に移行ガイドを読むよう警告が出ます。更新したい版を選んで「manifest を選んだ版に更新する」を押すと、確認ダイアログの後に Packages/manifest.json の該当箇所だけが書き換わります。間違えて更新した場合は「前の参照に戻す」で直前の状態に戻せます
  2. 版と CHANGELOG: 「現在の版」「前回適用した版」と、その間に何が変わったか（CHANGELOG の該当箇所）を表示します。「破壊あり」の変更が含まれる場合は警告が出るので、先に移行ガイドを確認してください
  3. マイグレーション（プレビュー）: 更新に伴ってデータの形式を直す必要がある件数を確認できます（この時点ではまだ何も変更しません）
  4. 更新を適用: ボタン 1 つで「データの形式を直す → ID/調整値の定数を作り直す → アセット管理の登録を揃える → 自動チェックを実行する」を順番に実行します。途中で失敗したらそこで止まり、それより後の手順は実行されません(前回適用した版も更新されません)
  5. テストを有効化する / エージェント向けスキルを更新: セットアップウィザードと同じ項目をここからも操作できます

更新後も、念のため上の「セットアップウィザードとは」の「完了チェック」を確認することをおすすめします（更新のたびに新しい設定項目が増えることがあります）。

困ったときは（Validation で確認する）

エフェクトや音が出ない・エディタの表示がおかしい等、うまくいかないときは、まず Validation（Tools > D-Drive > Validation > Run All）を実行します。

  • エラー（赤）: 実行時に何も再生されない・コンパイルが通らない等、実際に困る問題です。表示される説明文の指示に従って直します
  • 警告（黄）: すぐには困らないが、直しておいたほうがよい項目です。DD-SETUP- で始まる警告はセットアップウィザードの該当ステップを開くと直せます

Validation で解決しない場合は、プログラマー・テクニカルアーティストに相談してください。
