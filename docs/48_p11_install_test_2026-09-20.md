## 4. セットアップウィザード相当（手順 2〜3）

GUI ウィザード（`ProjectSetupWizardWindow`）はバッチでは動かせないため、ウィザードが呼ぶのと同じ非UI API を順に呼ぶ glue コードを**消費側プロジェクトの `Assets/Editor/InstallTestSetup.cs`** に書いて `-executeMethod` から実行した。

**重要: D-Drive 側のコード変更は行っていない。** 当初は `DDrive.Editor.CI` に `SetupHeadless()`/`ApplyUpdateHeadless()`/`EnableTestables()`/`DisableTestables()` を追加したが、呼び出している `ProjectSetupActions`/`ProjectSetupInspector`/`BootstrapSceneSetup`/`UpdateStepsFactory`/`UpdateActions`/`DDriveProjectSettings`/`DDriveVersion` がいずれも**既に public**であることに気づき、この D-Drive 側の追加を撤回して元のコードに戻した（`git diff` で無差分を確認済み）。実際に必要だったのは「`-executeMethod` は引数無しの static メソッドしか呼べない」という Unity CLI 側の制約を埋める薄い glue コードだけで、それは消費側の `Assets/Editor/InstallTestSetup.cs`（D-Drive の一部ではない）に置いた。

実行した非UI呼び出し(ウィザードの段と対応):

1. 依存の不足検査（`ProjectSetupInspector.InspectMissingGitDependencies`）→ ログ出力のみ
2. ProjectSettings 検査（`ProjectSetupInspector.InspectProjectSettings`）→ ログ出力のみ（自動変更しない。ウィザードと同じ方針）
3. 置き場所は既定のまま
4. 既定フォルダ・設定の生成（`ProjectSetupActions.EnsureDefaultFoldersAndSettings`）+ ID/Tuning 再生成（`ProjectSetupActions.RegenerateGeneratedCode`）

6. 起動オブジェクト配置（`BootstrapSceneSetup.PlaceInScene`）+ シーン保存（`Assets/Scenes/DDriveInstallTest.unity`）

### 発見した問題（未修正・フォローアップ）: 空カタログが Addressables に未登録のまま残る

上記の手順のあと `CI.ValidateAll` を実行すると **Error 12 件**（`ContentHashCatalogCoverageValidator`: 「カタログ 'XxxCatalog' が Addressables に未登録です」が AudioCatalog 以外の 11〜12 カタログ分）になった。原因は `EnsureDefaultFoldersAndSettings` が種別ごとの空カタログ `.asset` を作成するだけで、Addressables への登録（グループ + `DDriveCatalog` ラベル）まではしないため。ウィザードの「5. Addressables 同期」段も「各アセット作成時、または `Validation > Run All` の『修正』ボタンから同期される」という案内のみで、**まとめて同期するボタンが無い**。

消費側の glue コードで `AddressablesSync.SyncAll(log: true)` を明示的に呼んで解消した（`修正 0 件・カタログ 13 件・カタログ未登録 0 件` → `ValidateAll` Error 0）。**この「すべて同期」相当の操作をウィザード自体に追加することを推奨する**（フォローアップ、未実施）。README に注記を追加した。

### URP アセットの作成（消費側の対応、D-Drive 側の変更ではない）

上記のうち `VfxDataValidatorTests`(EditMode, 3件)・`ShaderPipelineAnalyzerTests`/`ModelDataValidatorTests`(PlayMode, 6〜7件)は URP が未設定であることが原因だった。消費側の glue コードから `Assets > Create > Rendering > URP Asset (with Universal Renderer)` 相当のメニューを実行して URP アセットを作成し `GraphicsSettings.defaultRenderPipeline`/`QualitySettings.renderPipeline` に割り当てたところ、これらは解消した（PlayMode 11→4 fail）。ただし EditMode 側では新たに `AssetIconServiceTests`/`MaterialThumbnailRendererTests` の 2〜3 件が `RenderTexture.Create failed`/MSAA 不一致で Fail するようになり、EditMode 全体の Fail 数は 22 のまま（ネットではほぼ変化なし、PlayMode 側は明確に改善）。この 2〜3 件は「-nographics + 自動生成した既定 URP アセットの MSAA 設定」由来と見られ、深追いはしていない（フォローアップ）。
