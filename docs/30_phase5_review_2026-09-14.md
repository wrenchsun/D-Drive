## P1 — 通常使用で誤動作 / リーク

1. **`SceneLoadingScreen.OnDisable` が `RunAsync` 未実行でも `ScenePreload.Release` を呼ぶ**
   （`Runtime/Loading/SceneLoadingScreen.cs:48-52`）。`ScenePreload.Release` は `RefCountedAsyncCache`
   経由で他者の参照カウントを減らしうるため、`autoStartOnEnable=false` で `RunAsync` を一度も呼んでいない
   インスタンスが `OnDisable` するだけで、他のロード画面/Preload 呼び出し元が保持している参照を誤って
   解放してしまう。修正: `_preloadStarted` フラグを追加し、`RunAsync` が実際に走った(= `ScenePreload.RunAsync`
   を呼んだ)ときだけ立てる。`OnDisable` はこのフラグが立っているときだけ `Release` する。テスト:
   `SceneLoadingScreenTests`(新規。未開始で `Release` されないこと / 開始済みでは従来どおり `Release` される
   ことの両方を確認)。
2. **`CameraFxManager` が `Camera.main` 差し替え時に旧ノードを破棄せず、カメラも元の親に戻さない**
   （`Runtime/Camera/CameraFxManager.cs:262-310`）。A→B→A のようにランタイム中に `Camera.main` が
   差し替わると、`DDriveCameraShakeNode` が孤児のまま積み上がり、旧カメラも旧ノードの子に入ったまま
   戻らない（`StopAll`/`OnSceneUnload`/`DDriveRuntimeBootstrap.Teardown` の経路でも復元しない）。
   修正: カメラごとに本来の親 + Sibling Index を記録し、`DetachCurrentCamera()`(新規)を
   ①差し替え検知(`AttachNode` 冒頭)②Camera.main 消失(`EnsureCameraNode`)③`StopAll(StopReason)`
   の 3 箇所から呼んで、旧カメラを本来の親へ復元 + 旧ノードを破棄する(Edit Mode では `DestroyImmediate`、
   Play Mode では `Destroy` に分岐)。テスト:
   `CameraFxManagerTests.EnsureCameraNode_SwapAtoBtoA_RestoresBothCameras_AndLeavesNoOrphanNode`。

### P1（Host 権威の抜け穴）

1. **発行者を検証しない**: `PresentationManager.OnReceiveSignalMsg`/`OnReceiveCancelMsg` は `HandleNetKey`
   の存在しか見ておらず、`NgoNetBridge.RequestBroadcastRpc` も型登録とレート制限のみで内容を見ずに
   `SendToAll` していた。さらに `Dispatch` が受信者の `senderId` を常に `NetworkManager.ServerClientId` に
   していたため、Client 発のメッセージが中継後は全ピアで「Host から来た」ものとして見え、発行者検証を
   実装しても機能しない状態だった。→ **対応**: `NgoNetBridge` の `ReceiveRpc`/`ReceiveUnreliableRpc`/
   `ReceiveToRpc`/`ReceiveUnreliableToRpc` に `originClientId` を追加し、`RequestBroadcastRpc` が
   `rpcParams.Receive.SenderClientId`(トランスポート付与、偽装不可)をそのまま中継するよう修正。
   `PresentationManager.NextHandleNetKey()` が `HandleNetKey` の上位 8bit に `LocalClientId` を埋め込み、
   `IsAuthorizedSender(senderId, handleNetKey)`(発行者一致、または Host からの信頼された中継/再送)で
   `OnReceiveSignalMsg`/`OnReceiveCancelMsg`/`OnReceivePlayMsg`(既知キー分岐)を検証し、不一致は警告して
   破棄するようにした。`CancelInternal` に入る直前(`OnReceiveCancelMsg`)でも `Interruptible` を再チェックし、
   偽造(または正規の Host 発でも)Cancel が Interruptible=false な演出を止められないようにした。
2. **HandleNetKey 衝突/偽装で台帳が混線**: `OnReceivePlayMsg` の既知キー分岐が中身を検証せず
   `RegisterActiveIfServer` していたため、A の台帳エントリが B の `StartNetTime`/`Seed` で上書きされ得た。
   → **対応**: 上記の発行者検証に加え、既知キー分岐でも `PresId` が既存エントリと一致しない場合は破棄する。

### P2

3. **PredictLocal の Host が自分のエコー受信前に late-join すると復元されない**: → **対応**:
   `PlayCosmeticNetworked` で `data.PredictLocal && _netBridge.IsServer` のとき、Broadcast 前に即座に
   `RegisterActiveIfServer` する。
4. **`OnClientConnected` が自分自身にも送り、foreach 中の辞書を再入で書き換える可能性**: → **対応**:
   `clientId == _netBridge.LocalClientId` の自己接続は early-return。台帳を配列にスナップショットしてから
   `SendTo` する。
5. **テストが全て Host 行為者、Client→Host 依頼経路が Fake に無い**: → **対応**: `FakeNetBridge` に
   `RequestBroadcastFromClient`(型登録+レート制限、`NgoNetBridge.RequestBroadcastRpc` と同じ検証)と
   `InjectReceive` を追加。`PresentationNetSecurityTests.cs`(新規)に Client 行為者の
   Play(PredictLocal)/Signal/Cancel、偽造 Signal/Cancel の破棄、Interruptible=false な偽造(正規送信元でも)
   Cancel の無視、を検証するテストを追加(既存の `DelayedNetBridge`/`NetPeer` インフラを再利用)。
6. **200ms テストの NetworkTime が Host/Client で完全に同一**: → **対応**: `DelayedNetBridge` に

   `SetDebugSimulatorParameters`/`DebugSimulator` が `[Obsolete("... is no longer supported and has no
   effect.")]` であり、ドライバ生成時に一切参照されない完全な no-op だったことが原因(呼び出し順序の
   問題ではない)。`NgoNetBridge` にアプリ層の送受信キュー遅延(`ConfigureAppLayerSimLatency`、開発ビルド
   + 明示指定時のみ)を実装して代替し、Ping/Pong で計測したアプリ層 RTT(`AppRoundTripMs`)を
   `NetDebugOverlay`/`NetCheckRunner`(`rtt_app_ms`)に追加した。
2. **Client 側で Signal 中継を観測できない**: `NetCheckRunner` の旧`signal=hit` ログは Host が
   `handle.Signal("hit")` を呼んだ直後にしか出ない実装で、Client 側の実発火は未検証だった。→
   `PresentationManager.OnNetworkReceivedPlay`(開発/確認ツール専用の新規イベント)を追加し、各ピアが
   `OnTrackFired` を購読して実際の発火を `signal_recv` としてログ出力するようにした。Host の意図表明は
   `signal_fire` に改名し、両方の `networkTime` を突き合わせて位相差を判定できるようにした。
3. **Late Join 直後に Presentation が Placeholder 解決される**: Client 接続直後の Late-Join スナップショット
   受信が、Client 自身のカタログ登録完了より先に処理されていたことが原因と確認。→
   `PresentationManager.SetRegistryReady(bool)` を追加し、`DDriveRuntimeBootstrap` がカタログ登録完了まで
   ネット受信の Play/Signal/Cancel を到着順にキューへ保留するようにした。
4. **偽造 Cancel の破棄ログが一部欠落**: 対象の演出が完了して台帳から外れた後に届いた偽造 Cancel は
   黙って破棄されていた。→ `OnReceiveSignalMsg`/`OnReceiveCancelMsg` に未知キー(対象が見つからない)の
   場合の破棄ログを開発ビルド限定・キーごとに 1 回追加した。
5. **(オーケストレーター追加指示)Host 停止時に Client が切断を検知しない**: `NetworkManager` の
   `OnClientDisconnectCallback`/`OnTransportFailure` を誰も購読していなかったため。→ `NgoNetBridge` が
   購読してログ出力 + `ClientDisconnected` イベントを追加、`NetCheckRunner` の heartbeat に
   `connected=0|1`、切断時に `disconnected=1` を追加した。自動再接続は実装しない(要判断)。

修正の詳細・コード上のコメント位置は [14_networking.md](14_networking.md) の「実装メモ（2026-09-14、6-0
実機確認で見つかった課題の修正）」節、ログ判定基準の更新は [docs/29](29_network_device_test.md) §3/§4、
ローカル結合確認の結果は同 §7 を参照。

## 第 4 弾（6-0 修正6: 実機確認 v2 で見つかった実バグの修正、2026-09-14 追記）

対象: 6-0 修正5 適用後の実機確認 v2([docs/29](29_network_device_test.md) §8「修正版 v2 での再確認」)で
見つかった新しい実バグ 1 件と、その後の切断確認(オーケストレーターが PC-B で実施)で見つかった小課題 4 件。

1. **P1(通常使用で誤動作)**: 遅延のある環境(実機確認では `-ddrive-sim-latency 200`)では、剣攻撃デモの
   VFX/SE(Time=0 のワンショット AtTime トラック)が Client の画面に一切描画/再生されなかった。原因は
   `PresentationManager.SeekInitialTracks` が `elapsed > 0` なら continuous でないワンショットを無条件で
   スキップしていたこと(遅延 0ms では Client の ServerTime 推定が Host より約 80ms 遅れて見えるため
   `elapsed` が偶然 0 にクランプされ発火していただけで、実際に遅延があると必ずスキップされていた)。→
   猶予(既定 0.5 秒、`PresentationManager` コンストラクタの任意引数 `remoteOneShotGraceSec`)を追加し、
   遅れが猶予以内ならワンショットを遅れて発火させる。判定用ログ `track_fired`/`track_skipped`
   (Manager 全体の event `OnAtTimeTrackFired`/`OnRemoteOneShotSkipped`)も追加した。
2. **P2(切断後の表示不整合)**: 切断後も `rtt_app_ms` が最後の値を表示し続ける → `NgoNetBridge` が
   自分(Client)の切断時に `AppRoundTripMs` を `null` にリセットする。
3. **P2(切断後のログ汚染)**: 切断後も `NetCheckRunner` が 5 秒おきに偽造 Cancel を送ろうとして
   `NgoNetBridge.Broadcast` の「未接続のため送信できません」警告が出続ける → `NetCheckRunner` に
   `Connected(bootstrap)` ヘルパーを追加し、切断中は送らないようにした。
4. **P1(通常使用で誤動作、切断確認で新規発見)**: 切断直後に Client の画面へ VFX が薄く描画される
   (接続中は出ていなかったものが切断の瞬間だけ出る)。原因はアプリ層遅延キュー(`NgoNetBridge` の
   `Delayed*` メソッド)に積まれた `UniTask.Delay` が切断後も生き続け、`NetworkTime` が 0 に巻き戻った
   状態で処理されて `elapsed=0`(=「今始まった正常な Play」)と誤認されたこと → `NgoNetBridge` に
   `CancellationTokenSource` を追加し、切断時にキューを破棄する。
5. **整理(表示の紛らわしさ)**: 起動直後(`role=off`)の heartbeat が `connected=1` と紛らわしく出る点、
   デバッグ表示に接続状態の行が無い点、`signal_recv` に `kind` が無い点も同じ PR でまとめて解消した。

修正の詳細は [14_networking.md](14_networking.md) の「実装メモ（2026-09-14、6-0 修正6）」節、ログ判定基準は
[docs/29](29_network_device_test.md) §4、実機/ローカル結合確認の結果は同 §8/§9 を参照。

## 第 5 弾（6-0 修正7: 実機確認 v3 で見つかった「切断後も VFX が残り続ける」実バグの修正、2026-09-14 追記）

対象: 6-0 修正6 適用後の実機確認 v3([docs/29](29_network_device_test.md) §8「修正版 v3 での再確認」の

1. **P1(通常使用で誤動作/リーク)**: Client 視点で Host との接続が切れても、ネット経由で開始した
   Presentation(および Spawn した VFX)が一切クリーンアップされなかった。原因は 2 点重なっていた:
   (a) `NgoNetBridge.ClientDisconnected` イベント自体(6-0 修正5 で追加済み)を購読して実際に演出を止める
   コードがどこにも無かった(6-0 修正5 時点では「Elapsed/Duration の自然完了に任せれば十分」と判断していたが
   誤りだった)。(b) デモアセット `PRES_Demo_SkillSlash` の Vfx トラックが `StopOnCancel=false` のままで、
   かつ参照先 `VFX_Player_Slash` の実体 Prefab(`vfx_sample.prefab`)の `ParticleSystem` が `looping=true`
   のため `VfxData.LifeMode=OneShot` でも自然終了しない(Cancel されない限り永遠に再生され続ける、接続の
   有無に関係なく発生する)。→ `PresentationManager.CancelAllNetworked()` を追加し、`DDriveRuntimeBootstrap`
   が Client 視点の切断時にだけ呼ぶ(Host 視点は対象外)。デモの Vfx トラックは `StopOnCancel=true` に
   Editor 経由で修正した。
2. **判定用ログ**: `NetCheckRunner` の heartbeat に `vfx_active=<VfxManager.ActiveCount>` を追加(既存の
   公開プロパティを使うだけで新規 API 追加は不要だった)。

修正の詳細は [14_networking.md](14_networking.md) の「実装メモ(2026-09-14、6-0 修正7)」節、ログ判定基準は
