## 2. GitHub リリースノートの下書き（v1.5.0）

```
## D-Drive v1.5.0 — D-Drive MCP（AI エージェント向けの Editor 操作ツール）

MINOR・追加のみ。Editor 組み込みの Unity MCP（jp.shiranui-isuzu.unity-mcp v4.2.0 以上）を入れたプロジェクトで、
D-Drive の Editor 機能を `ddrive_*` ツール 20 個として AI から直接呼べます。isuzu が無いプロジェクトでは何も増えません。

- 状態・案内: ddrive_status / ddrive_help
- Data: ddrive_asset_list / get / create / set / ddrive_editor_open
- 依存・削除: ddrive_asset_usages / unused / delete
- 検査: ddrive_validate / ddrive_validate_fix / ddrive_forbidden_api
- 生成・更新: ddrive_generate / ddrive_migrate / ddrive_compat / ddrive_compat_update / ddrive_release_check
- プレビュー・ビルド: ddrive_preview / ddrive_build_netcheck

安全装置: 書き込みは Project Settings > D-Drive > MCP の「書き込みを許可」（既定 OFF）が必要、Destructive なツールは confirm:true、
preview で何も書かずに結果だけ確認、Undo 対応、ID などの読み取り専用欄は拒否、Play Mode 中は書き込み拒否。
ポート競合ゼロ: ポートはプロジェクトパスから自動決定、Tools/Mcp/register-mcp.ps1 が接続情報から登録（ポート・トークンはリポジトリに置かない）。
互換性: ツール名・引数・返り値キーは契約（docs/42 §5.14 E-24、スナップショット mcp-tools.txt）。
詳細: docs/1002_ddrive_mcp.md、ProgrammerManual/mcp.html、CHANGELOG 1.5.0。
```

## 4. isuzu の版の検討（Q-2、2026-10-07）

v1.5.0 は **v4.2.0 固定のまま**出した（Q-2 の決定どおり）。リリース直前に最新を確認した結果:

| 項目 | 内容 |
|---|---|
| 最新 | **v4.4.2**（2026-09-17）。v4.2.0 の後に 4.3.0 / 4.3.1 / 4.3.2 / 4.3.3 / 4.4.0 / 4.4.1 / 4.4.2 |
| D-Drive のツールに関わる変更 | **無し**。CHANGELOG（4.3.0〜4.4.2）に `[McpTool]` / `[McpArg]` / `ToolCatalog`（発見規則・予約引数）/ ポート規則 / 記述子の形式 / `confirm`・`dry_run` の注入 / ジョブ化 の変更は書かれていない |
| 4.3.0 の Breaking で効くもの | (1) 返り値が `MaxResultSizeChars` を超えると切り詰めずに `isError` → D-Drive 側は `max_chars`（既定 4000）で自分で丸めるので通常は当たらないが、AI が `max_chars` を大きくしたときに `isError` になりうる（`MaxResultSizeChars` を明示していないツールが多い）。(2) 宣言していない引数はエラー（むしろ安全側）。(3) `console_read_logs` は `stack_trace:true` を付けないとスタックトレースを返さない（SKILL.md §2 の手順に追記が要る）。(4) `structuredContent` 廃止（`isuzu.py` / `measure-tokens.py` はテキスト側を読むので影響なし） |
| 4.4.x で便利になるもの | `call` がジョブの完了まで待つ（CLI）、`test_results` の `total` / `ranAny`、Editor 終了時の `editor_exited` |
| 上げるときの手順 | タグを `#v4.4.2` に書き換え → Unity を開き直す → `McpPortPolicyTests`（isuzu の `McpPortPolicy.Derive` と反射で突き合わせ）と `McpToolsSnapshotTests`（`mcp-tools.txt`）が green であること → `tools/list` に `ddrive_*` 20 個が載ること → `measure-tokens.py` を再実行して §10 を更新 → docs/20 §3 と SKILL.md の `stack_trace` 追記。MS2026 は別タイミングでよい（サーバーはプロジェクトごと） |
| 結論 | **v1.5.0 の直後に MCP-13 として v4.4.2 へ上げる**（1004 §1 に起票）。リリース前に上げなかったのは、ツール 20 個の契約を固めた直後に発見規則が変わる可能性を 1 つずつ切り分けるため |
