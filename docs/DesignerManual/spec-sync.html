仕様書との同期

企画が仕様書 Web アプリ（ブラウザで開く HTML の仕様書。学内・自宅どちらからでも入力できます）の「アセット」一覧に 1 件登録するだけで、D-Drive 側に Placeholder（空のデータ） が自動でできる機能です。プログラマーはその場でコードから ID を参照できるようになり、デザイナーは後から中身（音・エフェクト・見た目）を作り込みます。

2026-09-14 更新: 仕様書は Google スプレッドシートから Web アプリ（ブラウザで開く自作の HTML ページ）に変わりました。 企画側の入力先・使い方は Web アプリのページ上の説明を見てください。このページは「D-Drive 側でどう同期するか」の説明です。

できること

  • Web 仕様書の「アセット」一覧に新しく登録する → 同期すると、その種別・カテゴリ・識別子で ID 付きの空データ が自動的にできる
  • 表示名・カテゴリ・状態・担当・備考を書き換える → 同期すると、その項目だけが上書きされる（デザイナーが作り込んだ音やエフェクトの中身には触れません）
  • Web 側で「削除（アーカイブ）」にする → データ自体は消えず、「Web から消えた（Archive 候補）」という一覧に表示されるだけ（実際に消すのは人の判断）
  • 「調整値」ページに書いた数値（スカラー・表形式のどちらも）をプログラムのコードから読める（プログラマー向け）
  • D-Drive で作成・使用している状況（作成済みか・使用箇所数など）が Web 仕様書のアセット詳細に自動で反映される

同期のやりかた

  1. Tools → D-Drive → 仕様書と同期 を開く
  2. 「Web API URL」に仕様書 Web アプリの URL（D-Drive 連携用の URL。人が見る URL とは別）、「人向け SPA URL」に人がブラウザで見る URL を貼り、「読み取りトークン」「書き込みトークン」を入力して「設定を保存」（最初の 1 回だけ。トークンは管理者に発行してもらう）
  3. 「取得」ボタンを押す（少し待つと Web 仕様書の内容を読み込みます）
  4. 「新規」「変更」に出てきた行を確認する。チェックが付いている行が対象。外したい行はチェックを外す
  5. 「適用」を押す
  6. （企画向けに補足情報を返したい時だけ）「Web に送信」を押すと、種別・カテゴリの選択肢や、D-Drive 側の作成状況・使用箇所数が Web 仕様書に反映されます
起動時に自動でチェックされます。 Unity を開いたときに仕様書に変更があると、Asset Browser のツールバーに「仕様書に変更 n 件」というボタンが出ます。押すとこの同期ウィンドウが開きます。自動では作成・上書きはしません（見つけるだけ）。
同期のたびに、repo 直下の Specs/assets.json・Specs/tuning.json というファイルが更新されます。これは Web 仕様書の内容をそのまま git にコミットする記録用ファイルで、「いつ・何がどう変わったか」を git log で追えるようにするためのものです（仕様書 Web アプリ自体には変更履歴の機能がないため、その代わりを git に持たせています）。このファイルを手で編集する必要はありません。

画面の見かた

区分意味
新規Web 仕様書にあるが D-Drive にまだ無い行。チェックを付けたまま「適用」すると Placeholder が作られる
変更D-Drive に既にあるデータと、表示名・カテゴリ・状態・担当・備考のいずれかが違う行。「適用」すると違う項目だけ書き換わる
Web から消えた（Archive 候補・表示のみ）以前 D-Drive にあるものとして同期されたのに、今回の Web 仕様書に見当たらない行（Web 側で削除・アーカイブされた等）。ここに出ても何も自動では起きません。削除するかどうかは人が判断してください
衝突（適用不可）同じ「種別＋識別子」が 2 件ある、識別子が英語 PascalCase になっていない、種別が不明、などの理由で読み込めなかった行。Web 仕様書側を直してから再度「取得」してください
「衝突」に出た行は絶対に無視しないでください。その行だけ同期されず、コードから参照できるようになりません。よくある原因は「識別子が sword_slash（小文字・アンダーバー）になっている」「同じ識別子を別の行にも登録してしまった」です。

「担当」「状態」はどこに反映される？

同期されたデータの Inspector を見ると、「Assignee（担当）」欄に仕様書の担当がそのまま入ります。「状態」は Tags 欄に State/仮 のような形で入ります（専用の欄ではなく、既存の Tags を使っています）。

仕様書を開くボタン（Inspector）

同期すると、そのデータの SpecUrl に Web 仕様書のアセット詳細ページの URL が自動的に設定され、Inspector 最上部に 「📄 仕様書を開く」 ボタンが出ます。押すとブラウザで該当ページが開きます（「人向け SPA URL」が設定されていない場合はボタンは出ません）。

調整値（プログラマー向け）

「調整値」ページに書いた数値（ヒットストップの秒数、影響力の係数など）は、同期すると D-Drive の内部データに取り込まれ、プログラムのコードから次のように読めます。

using DDrive.Generated; // TUNING.キー定数 / TUNING_TABLE / TUNING_COLUMN
using DDrive.Runtime.Tuning;

// スカラー
float hitStopSec = Tuning.GetFloat(TUNING.CombatHitStopSec, defaultValue: 0.05f);

// テーブル型（2026-09-14 追加。行×列の表を丸ごと Web 仕様書で編集できる）
int slimeHp = Tuning.GetTableInt(TUNING_TABLE.EnemyParams, "Slime", TUNING_COLUMN.EnemyParamsHp, defaultValue: 10);

企画が「調整値」ページの数字を変えて同期するだけで、次にゲームを実行したときからその値が反映されます（コードの書き換え不要）。キーが仕様書に無い場合は既定値が使われ、ゲームは止まりません。

新規作成ダイアログから 1 件だけ選んで作る（2026-09-14 追加）

まとめて同期する以外に、Asset Browser の「新規」ダイアログの「仕様書から選ぶ」から、仕様書にあるけどまだ D-Drive に無いものを 1 件だけ選んで作ることもできます。急いで 1 つだけ欲しい時に便利です。詳しくは Asset Browser のページを参照してください。

選択肢・実状態を Web 仕様書へ送る（2026-09-14 更新）

「Web に送信」ボタンを押すと、次の 3 種類だけが Web 仕様書へ送られます。企画側が入力した本文や調整値の値そのものが D-Drive から書き換わることはありません（安全のため送信できる内容がサーバー側で固定されています）。

送るもの内容
選択肢種別（AssetType）一覧・既存アセットから収集したカテゴリ一覧。Web 側の入力プルダウンが D-Drive の最新一覧と揃う
アセットの実状態作成済みか・使用箇所数・最終同期時刻（読み取り専用としてアセット詳細に表示される）
調整値の使用状況コードから参照されていない調整値キーの一覧（「未使用」の目印として使う）

よくある質問

  • Q. 中身を作り込んだ後に Web 仕様書の表示名を変えたら、上書きされて消える？ → 表示名・カテゴリ・状態・担当・備考だけが書き換わります。音源・カーブ・Prefab など実際の中身は同期では一切触りません。
  • Q. Web 側で削除したら本当に消える？ → 消えません。「Web から消えた」一覧に出るだけで、実際に削除するかは人が判断します。
  • Q. 種別を「ControlSkin」にしたのに新規作成されない → ControlSkin は「ボタン用」「スライダー用」の 2 種類があり、どちらを作るかを D-Drive 側で決められないため自動作成をスキップします（Console に警告が出ます）。Asset Browser の「新規」から手動で作成してください。
  • Q. トークンはどこでもらう？ → Web 仕様書の管理者（admin ロール）が発行します。読み取り用・書き込み用の 2 種類があり、両方をこの同期ウィンドウの設定に貼ります。トークンは Unity のこの PC だけに保存され、git には入りません。
