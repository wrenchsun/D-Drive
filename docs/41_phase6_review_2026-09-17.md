### runtime

**P1-1. `PoolService` のラッパー再利用（6-2）で、回収された Instance の `Despawn` が別 Instance の貸出を取り消す**

`Assets/DDrive/Foundation/Pool/PoolService.cs:76-86`（evict 時に `ForceReturn` → `Free.Pop()` で**同じラッパー**を新しい借り手へ渡す）、`:181-205`（`ForceReturn` は `pool.Active.Remove(obj)` が成功すれば無条件に `SetActive(false)` + Free へ積む）。

6-2 以前は `Rent` のたびに `new PooledObject` していたため、evict された Instance A が持つ旧ラッパーは Active に居らず `Return(A.Pooled)` は冪等ガード（`:185`）で無視されていた。今はラッパー W が A → B に引き継がれるので、**A 側の `Return(W)` が B の貸出を取り消す**（ABA 問題）。

影響するのは evict を通知する `IPoolable` を持たない Manager: `PrefabsManager`（`:143-149` で `SetLimit` するので evict が起こりうる、`:171` で `Pooled` を保持、Tick は空 `:386-389`）と `ModelsManager`（`:138-144, 165, 196-232`）。`VfxManager` / `AudioManager` は `VfxInstancePoolable` / `SeSourcePoolable.OnReturn` → `CleanupBookkeeping` で evict 時に台帳から外れるため影響なし。

再現: `PrefabData.Flags.Pool = {Kind=Pooled, MaxCount=1}` で `Spawn`→A、`Spawn`→B（A が evict、B は A と同じ GO・同じラッパー W を受け取る）、ゲーム側が A を `Despawn` → `Active.Remove(W)` が成功し **B の GameObject が非アクティブ化され Free に積まれる**。B の Handle はまだ有効。続けて `Spawn`→C で W が再び Pop され、B と C が同じ GameObject を二重に保持する。`StopAll` でも A→B の順で同じことが起きる。

修正: (a) `Rent` の evict 経路だけ `Pop` したラッパーを使わず `new PooledObject(popped.GameObject, prefab)` に差し替える（evict は例外経路なので alloc を許容し、通常の Return → Rent サイクルは 0 alloc のまま）。(b) 恒久策として `PrefabsManager` / `ModelsManager` にも evict 通知を入れ、回収時に台帳から外す（**「evict 後も A の Handle が生きていて B の GameObject を操作できる」という別の実害も同時に解消する**）。

回帰テスト: 既存の `Tests/Runtime/PoolServiceTests.cs:53-76` は `low` と `third` が同一オブジェクトになった今も通ってしまう（テスト自体が誤りなのではなく、追加が必要）。「evict 済みラッパーを `Return` しても新しい借り手が影響を受けない」を追加する。

1. **`CatalogContentHashGate` が Client 切断時に保留期限を掃除しない**（`Runtime/Net/CatalogContentHashGate.cs:106-107, 219-244, 246-267`）。Gate は `INetBridge.ClientConnected` しか購読しておらず（`:68`）、切断通知（`NgoNetBridge.ClientDisconnected`。`INetBridge` には無い）を見ていない。Client が接続後 5 秒以内（ハッシュ送信前）に切断すると、Host は 5 秒後にタイムアウト扱いにし、リリースビルドで `LogError` + 居ない id への `DisconnectClient` + `ClientDisconnectedForMismatch` を発火する（NGO 側は例外にならないので、誤るのはログ・状態・イベント）。修正: `INetBridge` に `ClientDisconnected` を足すか Bootstrap が橋渡しして `_pendingHostSideDeadlines.Remove(clientId)`。
2. **同 Gate: Host のカタログ登録が未完了でもタイムアウトで切断 / 警告する**（`:140-144` と `:219-244`）。期限は `ClientConnected` 時点から数えるが、Host の `_registryReady` は `DDriveRuntimeBootstrap.RegisterCatalogsAsync`（`:520-569`）完了時で、`AssetRegistry.RegisterCatalogAsync`（`:57-63`）は Preload エントリのロードを await する。Host の登録が 5 秒超かかると正規 Client を切断し、その後 `FlushPendingBeforeReady` が切断済み Client へ `SendTo` する。修正: `Tick` で `_pendingBeforeReady` に該当 senderId があれば期限切れにしない、または起算を `_registryReady` 後にする。
3. **`Tuning.GetTable*` の未登録 / 型不一致経路が呼び出しごとに文字列を連結する**（`Runtime/Tuning/Tuning.cs:266-277, 279-290`）。`HashSet.Add` の**前**に `tableKey + "/" + rowId + "/" + columnKey` を毎回生成しており、スカラー版（`:109-128, 130-140`）が 0 alloc なのと非対称。Tick から読むゲームコードでキーが無いと毎フレーム 3 回の string alloc（`#if DEVELOPMENT_BUILD` の外側）。修正: `HashSet<(string,string,string)>`（ValueTuple なので boxing 無し）にする。

### runtime

- `CatalogContentHashGate.cs:129-130` — `_clientHashSent = true` を `Broadcast` の前に立てるため、将来 `Broadcast` が no-op になる `INetBridge` 実装に対して脆い（現状は `OnNetworkSpawn` で購読するので発火時点で必ず Spawn 済み。誤検知欄参照）
