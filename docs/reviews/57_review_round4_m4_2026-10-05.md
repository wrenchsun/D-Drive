## FY-R-02: 立場別・マーカー時刻別の発火の表（作り直し）

前提: 「開始位置 s」= 受信した端末での `Max(0, NetworkTime − StartNetTime)`（受信時に 1 回だけ計る。Registry 準備待ちで保留された場合は準備完了時に計る）。マーカーの時刻 t を次の 4 つに分ける。

- **M0**: t = 0
- **Mw（窓内）**: 0 < t ≤ s かつ s − t ≤ 0.5
- **Mo（窓外 = 古い）**: s − t > 0.5
- **Ml（後）**: t > s（以降の `Tick` で跨いだときに発火。全立場で 1 回）

発火の条件は全立場で同じ: **s = 0 なら全部、s > 0 なら t ≥ s − 0.5 のものだけ**（M0 は s ≤ 0.5 のときだけ）。発火は `Play` の中ではなく**最初の `Tick`**。

**確認したこと（問題なし）**

- **種別**: 5 本のカーソルが同じ式（`SkipMarkersOlderThan` の 5 本の `while`）で、マーカーは収集時に時刻で並べ替え済み（`CutsceneManager.cs:680-684`）なので「古いものから順に飛ばして止まる」で正しい。同時刻のマーカーは同じ判定。
- **受信経路**: 通常の受信・Host の中継・Late Join の `SendTo`・保留の再処理がすべて `OnReceivePlayMsgInternal` を通る。Late Join の再送は送信者自身には届かない（`OnClientConnected` は新規の clientId にだけ送る）。
- **境界**: s = 0.5 ちょうどで M0 は発火（`> 0.5` で無音）。s ≥ 尺（尺 > 0）なら復元しない。s が負・未同期なら 0 に丸めて全部発火（`Elapsed > 0` が偽で何も飛ばさない）。
- **`_predictedKeys`**: キーは Broadcast の**前**に記録するので、同期配送（`LocalLoopbackBridge`、Host の自分宛て）でも取りこぼさない。戻ったときは既存インスタンスの有無より先に除くので覚えが残らない。キーは発行者のビット（`HandleNetKeyIssuerBits = 8`）で他の端末と衝突しない。同じキーのメッセージが 2 回届いても、1 回目で覚えが消え、2 回目は既存インスタンスがあれば何もしない・無ければ（=ローカルで止めた後）通常の受信として扱う（ReliableOrdered では 2 回届かないので実害なし）。予測再生なしの送信者・他人の送信は覚えに入らないので影響を受けない。Cancel は自分では止めず Broadcast するので「Play が戻る → Cancel が戻る」の順になり、覚えの誤用は起きない。Client の切断は `DDriveRuntimeBootstrap.ResetNetworkedState`（`StopNetworking` と切断時の両方）経由で `_predictedKeys.Clear()` に届く。
- **Presentation との一致**: `PresentationManager.cs:1572-1580`（`elapsed > 0f` かつ `elapsed − track.Time > grace` でスキップ）と式・境界が同じ。違いは発火のタイミング（Presentation は受信した `Play` の中、Cutscene は最初の `Tick`）と、Presentation の猶予がコンストラクタ引数（既定 0.5、`DDriveRuntimeBootstrap` は既定値のまま）で Cutscene は定数であること。持ち込み先が Presentation の猶予を変えると両者がずれるが、今は変える手段が公開されていないので問題なし。

### (b) 旧版が将来の書き方を見ても壊れない / 誤って許可しないか

上の表のとおり、**新しい接頭辞で拡張する限り、旧版は必ず安全側（当たりは Error のまま）**になる。例外は「今の接頭辞の後ろに修飾を足す」形だけで、これは契約の文面で禁じておけば起きない。旧版が新しい規則名で Warning を出すのは、持ち込み先が版を混ぜない限り起きない（MS2026 は 1 つの版を参照）。
