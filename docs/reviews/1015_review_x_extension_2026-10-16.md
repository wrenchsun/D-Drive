## 総評

- **既存データ・既存種別の挙動は「追加のみ」で保たれている**と読めた。`AssetType.Extension` は末尾（= 19、`enums.txt` +1 行のみ）、`CatalogEntry.KindKey` は末尾フィールドで既存カタログは空のまま読め、`CatalogContentHasher.MixString` は空文字で何も混ぜないので既存 ContentHash は不変。`AssetRegistry` は `_byType` を従来どおり持ち、`_byKind` は KindKey が空でない Entry だけに作る。`AssetNamingService` / `AssetCreationService` / `AssetReorganizer` の KindKey 版は `type != Extension` で必ず従来の関数へ落ちる（E26_BuiltInTypes_AreUnchanged が全種別で確認）。`public-api-*.txt` / `enums.txt` / `editor-contract.txt` は追加行のみ（削除・変更行 0）。`mcp-tools.txt` / `validator-severity.txt` / `net-messages.txt` は無変更。
- **起動配線（X-2）の順序・例外隔離・対称性は仕様どおり**。組み込みの Register → facade Bind → `BuildModules()`、破棄は `StopAll` → module 逆順 `Unbind` → module の Manager の `Unregister` → 組み込みの `Unregister` → 組み込み facade の `Unbind`。module 0 件なら従来と完全に同じ。Tick の定常経路には何も足していない。
- **ただしリリース前に直すべき穴が 4 つある**:
  - **`EditorModuleHost` が module の `Bind()` / `Unbind()`（= 静的ファサードの結び付け）を Edit Mode でも呼び、しかも module のインスタンスは `ModuleRegistry` が 1 つだけ持って Bootstrap と共有している**。雛形の窓は `OnEnable` で Host を作るので、窓を開いたまま Play に入る・Play 中に窓を閉じると、**ゲーム側の `Samples.Play` が Edit 用の Manager に流れる / 何も起きなくなる**（**X-R-01**）。`BindFacades = false` の多重起動でも同じ取り合いが起きる。
  - **provider の `Prefix` が ID 定数名の接頭辞判定に全種別で効く**ため、持ち込み先が種別を 1 つ足しただけで、**組み込み種別の手付け名アセットの生成定数名が変わりうる**（生成コードの互換 = 追加のみ、に反する。`AssetIdGenerator` 自身のコメントが「KnownPrefixes への追加は禁止」と書いている理由そのもの）（**X-R-02**）。
  - **`AssetKindRegistry` の発見だけ `Type.IsVisible`（public）を見ていない**。§5.14 の発見規則（FX-R-14「タグ後に変えると外部実装の挙動が変わるのでタグ前に確定」）と E-26 の記述（public）に反し、internal な provider も拾う（**X-R-03**）。
  - **公開してから困るシグネチャ**が残っている: `DDriveBootstrapContext.ForEditorPreview`（任意引数 17 個。「Context の項目は今後も追加のみ」と書いた直後に、項目を足すとこのメソッドの引数を変えるしかない = MAJOR）、`EditorModuleHost` のコンストラクタ（同じ形）、`UxCard.Rows`（内部の可変 `List<UxRow>` をそのまま公開）（**X-R-04**）。
- P2 は 8 件。主なもの: KindKey / DisplayName が組み込みの種別名と衝突しても弾かれず、`ddrive_validate` の `type:<名>` は provider を先に見るので**組み込みの scope を乗っ取れる**（X-R-05）、**プレイヤービルドでの module 発見がリフレクション頼みで IL2CPP のコード除去に無防備**（X-R-06）、**`ctx.Events` がどの `AssetEventDispatcher` にも繋がっておらず、雛形の窓が出している「イベント」欄が実際には何もしない**（X-R-07）、`editor-contract.txt` が型引数・名前空間・既定値を落とすので **UxPublicApi の型変更を検出できない**（X-R-08）。

- **シリアライズ**: `CatalogEntry.KindKey` は末尾フィールド（既存フィールドの順序不変）。既存の `.asset` に欄が無ければ Unity は空文字で読む。`AssetCatalog.AddOrUpdate` は Entry を丸ごと置き換えるので KindKey も保たれる。`new CatalogEntry` を組み立てる 3 か所のうち `AssetCreationService` / `AssetReorganizer` は KindKey を詰め、`EditorAnchorRegistry` は組み込み種別だけを登録するので空で正しい。
- **ContentHash**: `MixString(hash, "")` / `null` は何も混ぜないので、組み込み種別だけのカタログのハッシュは X-1 前と同一。`net-messages.txt` 無変更。
- **Registry**: `_byType` は従来どおり全 Entry を持ち、`Entries(type)` の戻りは不変。`_byKind` は KindKey が空でない Entry だけ。`Entries(type, null/"")` は `Entries(type)` に委譲。`IAssetRegistry.Entries(type, kindKey)` は既定実装つき（外部の Fake を壊さない。既定実装は毎回 List を作るが、定常経路ではない）。
- **命名・カタログ・既定 Load**: KindKey 版の 4 関数は `type != Extension` で必ず従来の関数に落ちる（KindKey を渡しても無視）。`AllCatalogNames` は Extension を provider ごとのカタログ名に展開し、provider が無ければ何も足さない（従来の列挙と同じ）。`AddressablesRegistrationValidator` の Preload 判定も KindKey 版に置き換わったが、組み込み種別では同じ値。
- **Validator**: `ValidatorRegistry` は `IKindValidator` の絞り込みを `assetType == Extension` のときだけ行う。組み込み種別と `IUniversalValidator` の適用は不変。`validator-severity.txt` 無変更。
- **ID 生成**: `TryAcceptDefinition` は Extension で KindKey 空のときだけ Error 1 件 + 飛ばす。組み込みの定義は従来どおり受理（X-R-02 の定数名の件を除く）。`FindDefinitions` の除外に `ExternalContract.Tests*` を足したが、以前のこのアセンブリに `[AssetIdDefinition]` 付きの Data は無かった（`ExternalDummyData` は属性なし）ので、開発リポジトリの `AssetIds.g.cs` は変わらない。
- **AssetBrowser**: 種別フィルタは `"All"` + 組み込み（`None` / `Extension` を除く）+ provider の DisplayName。組み込みのラベルは `LabelOf` が `type.ToString()` を返すので従来と同じ文字列で照合される。
- **発見**: `ReflectionTypeLoadException` は `e.Types`（null 要素は飛ばす）で続行。コンストラクタの例外は警告して飛ばす。重複 KindKey は型の完全名の序数比較で先勝ち + 警告 1 回（`WarnedDuplicates`）。結果はキャッシュで、走査は初回のみ（Editor の道具からの呼び出しだけで、Runtime の定常経路からは呼ばれない）。

### X-2（起動配線）

- **組み込みの順序は不変**: `BuildModules()` は `Build()` の末尾（組み込みの Register と `if (BindFacades)` の facade Bind の後）、`_built = true` の前。Teardown は `loop.StopAll(SceneUnload)` の直後に `TeardownModules()`、その後に組み込みの `Unregister` 群と facade の `Unbind`。`loop == null` の経路でも `TeardownModules()` が冪等に呼ばれる。module 0 件なら `_moduleRunner` は null で何もしない。
- **例外隔離**: `CreateManagers` / `Bind` は 1 つの try で module 単位。null 要素は module ごとに警告 1 回。`Unbind` は個別の try。`Order` の例外は 0 扱い + 警告。並びは型名で並べてから `Order` で安定な挿入ソート（`List.Sort` の不安定さを避けている）。
- **Unbind の対称性**: `_bound` に Bind 成功分だけ積み、逆順に Unbind。module の Manager は `_managers` の逆順で `Unregister`（Bind 失敗の module の Manager も外れる）。
- **Context**: `readonly struct` + get 専用 + internal コンストラクタ。`in` 渡しで boxing・コピーの増加なし。Bootstrap の `NetBridge` は Loopback が既定で null にならないので `NetworkTimeSource` は安全。
- **ModuleRunner の Editor / Runtime 共用**: 実装は `GameLoop` と `IDDriveModule` だけに依存し、UnityEditor を参照しない（Runtime asmdef の規則どおり）。共用自体は妥当（X-R-01 は「何を呼ぶか」の問題）。

### X-3（Editor/Ux の公開）

- **既存の窓の挙動**: 差分は `internal` → `public` と、公開しない道具（`UxRow.MakeInput` / `IsCompound` / `TierName` / `IssueKey` / `MakeIssue`、`DataSwitcher` の静的ヘルパー、`TuneCategories.Words` / `HasWord`）を `internal` に戻しただけ。`TuneCategories.Names` の配列 → `IReadOnlyList` は公開前の変更なので破壊ではなく、利用側（添字アクセス・`Count`）はそのまま通る。
- **internal 型を引数に取る public メンバー**: UxPublicApi の全行を見て、引数・戻り値に internal 型（`UxTestHooks` / `UxScreenshot` / `UxPalette` ほか）が出るものは無い（出ていればコンパイルエラーになるので構造的にも起きない）。`ParamValue`（Foundation）は public。`object` 型の公開は `UnityEngine.Object`（Undo の対象）のみで妥当。
- **`UxPreviewDriverBase`**: 二重 Dispose 無害、Dispose で全イベントを解除、`OnReset` の例外は警告で続行、シーン保存直前だけルートを残す（DontSave は書き出されない）、プレハブモード中はステージに置く。`EditorPreviewSweeper` の掃除対象になる名前接頭辞を強制している。
- **`EditorModuleHost`**: 二重 Dispose 無害、Dispose で `update` を外してから `StopAll` → `Stop`。二重 Bind は Host 単体では起きない（Start は 1 回だけ）。

### X-4（provider）

- **組み込み種別の経路は不変**: 空状態は `HasSample` が true なら従来どおり `CreateSample()`、false でも `KindKeyOf(typeof(TData))` が空なので provider を引かずボタン無し。ヒーローの「確認用シーン」も KindKey 空で何も足さない。`ManualLauncher.OpenPage` は外部 key に一致し**かつ**組み込みのページファイルが無いときだけ外部へ流れる（組み込みが先）。
- **サンプル作成**: `configure`（`CopySerialized`）は `Create` の中で Id 採番・`StampNew` より前に走るので、テンプレートの Id 0 / Version で上書きされない。Flags は種別の既定 Load を残してから上書き。テンプレートは作成後に破棄。保存済みの Data は `RegisterExisting` だけ。
- **発見**: `TypeCache`・`IsVisible`・非 abstract・非 interface・ジェネリック定義でない・public 引数なしコンストラクタ・テストアセンブリ除外・型名順・重複は先勝ち + 警告 1 回・コンストラクタ例外は `Debug.LogException`。§5.14 の規則どおり。
- **シーン**: 未保存の確認・既に開いていれば開き直さない・`Setup` の例外は警告。

### X-5（雛形・MCP・契約テスト）

- **雛形の Runtime**: `Time.*` / `Instantiate` / `Resources.*` / `Addressables.*` / `UnityEditor` の参照なし。`SampleManager.Tick` は `for` の後ろからの走査で LINQ・クロージャ・boxing なし（`Play` で `Instance` を 1 個 new するのは許容範囲）。未 Bind のファサードは no-op。Validator の Code は `SMP-` 接頭辞。asmdef は Runtime（Foundation / Runtime 参照、全プラットフォーム）と Editor（Editor 専用、`DDrive.Editor` + Runtime 参照）の 2 本で参照は過不足なし。`Samples~` 配下に `.meta` は無く（Unity から見えない置き場なので正しい）、`package.json` の samples に登録済み。`ExtensionTemplateCompilesTests` が丸ごとコピーでのコンパイル・発見・`[DataEditor]`（Order 0 の `SampleEditor`）まで確認している。
- **MCP**: `mcp-tools.txt` 無変更（引数の名前・型・必須は同じ。`type` / `scope` が受ける値が増えただけ）。`ddrive_validate` の行の `type` 欄は Extension のときだけ KindKey、組み込みは従来の enum 名。`FieldTables.TryResolve` は組み込みを先に解決する（X-R-05 の `ParseType` を除く）。
- **契約テスト**: E-25（PlayMode 6 件、Bootstrap を実際に作って順序・対称性・例外・null 要素・Context を確認）、E-26（発見・重複・既定除外・命名・既定 Load・カタログの KindKey・ID 生成・KindKey 無しの拒否・`IKindValidator`・Registry index）、E-27（窓が VfxEditor と同じ USS クラスで組まれる・部品・▶・自動停止・Host・`[DataEditor]`・コンストラクタ / 抽象メンバー / USS）、E-28（発見・一連の流れ・provider 無し・失敗時の継続・マニュアル解決）、E-29（クラス・接頭辞・組み込みのクラス集合）。実データ（`Assets/GameData`）には書かず、一時フォルダ（`Assets/Tests/DDriveTemp/…`・`TestTempFolder.Root`）を TearDown で消している。`IncludeTestAssemblies` は SetUp / TearDown で保存・復元 + `Refresh`。空振りの assert は見当たらない（X-R-02 / X-R-21 / X-R-22 の「検証範囲が狭い」を除く）。
