# 35. チュートリアル動画の台本（6-4）

関連: [11_tasks.md](11_tasks.md) 6-4 / [DesignerManual/Readme.html](DesignerManual/Readme.html) / [DesignerManual/getting-started.html](DesignerManual/getting-started.html) / [23_manual_verification_2026-09-11.md](23_manual_verification_2026-09-11.md) / [28_manual_verification_phase5.md](28_manual_verification_phase5.md)

> **収録・ナレーション・公開は人の作業**（[11_tasks.md] 6-4 の P6 決定事項）。このドキュメントはエージェントが用意した**台本**（撮るべき操作の手順・映すもの・話す内容）まで。実際の画面録画・音声収録・動画への書き出し・共有先への公開はユーザーが行う。
>
> 台本中のメニューパス・ボタン名・ウィンドウ名は、実装済みのコード（`[MenuItem]` 属性・各エディタの実装）と `docs/DesignerManual/*.html` の記述に合わせている。収録前に該当ページ（各動画の「参照ページ」）を読み、実際の Unity 画面と台本の文言が食い違っていないか確認してから撮ること（実装が進むと UI 文言が変わることがある）。

---

## 0. 全動画共通の収録ルール

### 0.1 画面・録画設定

- **解像度**: 1920×1080（16:9）で録画する。Unity のウィンドウレイアウトは Asset Browser / 各専用エディタ / Inspector が同時に見える広さを確保する（ノート PC の狭い解像度のまま録らない）
- **文字サイズ**: Unity の Editor フォントサイズ・Console の文字が動画に書き出した後も読める大きさにする（等倍で潰れそうならズームインするか、Unity 側のフォント設定を一時的に上げる）
- **録画範囲**: Unity 全体ウィンドウ、または該当エディタウィンドウを最大化してから録る（デスクトップの他アプリ・タスクバーの通知等が映らないようにする）

### 0.2 マウス・操作の見せ方

- クリックする直前に**一度マウスを止める**（早すぎる移動は視聴者が追えない）
- ドラッグ操作（トリミング範囲・Anchor のスライダー・タイムラインのトラック等）は**ゆっくり**動かし、値の変化が画面に映る速さで止める
- 可能ならマウスクリックを可視化するツール（クリック時に円が広がる等の OS/録画ソフトの機能）を使う。無ければ「今ここをクリックします」と一言添えてから押す

### 0.3 映してはいけないもの（個人情報・機密）

- **実在の URL・メールアドレス・トークン・API キーを画面に映さない。** 特に以下は事前に隠すか、ダミー値に置き換えてから収録する:
  - 発注ツールの「Web API URL」「人向け SPA URL」（`Tools > D-Drive > 仕様書と同期` ウィンドウ）
  - 読み取り/書き込みトークンの入力欄
  - 発注ツール（ブラウザ）にログインしている Google アカウントのメールアドレス表示部分
  - Windows のユーザー名がフォルダパスに出る場面（`C:\Users\<名前>\...` 等）。可能ならタイトルバー・パスバーを映さない構図にする
- 上記が映り込むダイアログ・ウィンドウを開く必要がある場合は、該当欄をぼかす／該当ウィンドウを閉じてから次のカットに進む、のどちらかで対応する
- チーム内の実名・実際のガントチャート・実際の発注内容（本番の企画データ）は映さない。動画用に「練習用」「Demo」等と分かるダミーの表示名・識別子を使う

### 0.4 収録前の確認

- 対象の Unity プロジェクトが**最新の main ブランチ**であること（台本の UI 文言が古い実装のままにならないように）
- 収録専用に作ったデータ（練習用の SE・VFX・Presentation 等）は、収録後に**安全な削除**（[DesignerManual/asset-browser.html](DesignerManual/asset-browser.html)「安全に削除する」）で片付けるか、Archive しておく。本番の `Assets/GameData/` を汚さない

## 1. 動画①: SE を1つ登録して鳴らす（目安 5分）

**目的**: Asset Browser への登録から試聴までの最短フローを見せる。[DesignerManual/getting-started.html](DesignerManual/getting-started.html) の手順4〜7に相当。

**参照ページ**: [se-data.html](DesignerManual/se-data.html) / [asset-browser.html](DesignerManual/asset-browser.html) / [audio-editor.html](DesignerManual/audio-editor.html)

**事前準備**:
- 開くシーン: 任意（Asset Browser はシーンに依存しない。空でよい）
- 用意する素材: 短い効果音ファイル（.wav、1〜2秒、無音区間ありのもの — トリミングのデモに使える）を `Assets/SourceAssets` 以下の適当な場所に置いておく（種別フォルダの外でよい。カット2でわざと「置く場所」を説明する）

| カット | 画面操作 | 映すもの | ナレーション原稿 |
|---|---|---|---|
| 1 | `Tools > D-Drive > Asset Browser` を開く | メニューから開く操作、Asset Browser 全体 | 「D-Driveでは、音やエフェクトなどの素材を全部『Asset Browser』というウィンドウから管理します。まずはこれを開きましょう。」 |
| 2 | Project ウィンドウの音声ファイルを Asset Browser のウィンドウ上へドラッグ＆ドロップ | ドラッグ中のマウス、ドロップした瞬間 | 「音声ファイルは、Asset Browserの上にドラッグ＆ドロップするだけで登録できます。ドラッグ＆ドロップで作れるのは効果音だけ、というルールがあります。」 |
| 3 | 登録ダイアログで表示名（例:「収録用サンプル音」）・識別子（例: `TutorialSample`）を入力し「作成」を押す | ダイアログの入力欄、識別子が英語PascalCaseであること | 「表示名は日本語でOKです。識別子は英語で、プログラマーがコードから呼び出すときの名前になります。先頭は大文字、記号やスペースは使えません。」 |
| 4 | 一覧に追加された行をクリックして選択 | 一覧の新しい行、選択状態 | 「作成すると一覧に追加されます。クリックして選びましょう。」 |
| 5 | 下のプレビューバーの「▶ 再生」を押す | 再生ボタン、再生中の表示 | 「下のプレビューバーの再生ボタンで、ゲームを実行せずにその場で試聴できます。」 |
| 6 | Inspector の Volume を 0.5 前後に変更し、もう一度▶で確認 | Volume スライダーの変化、再生 | 「Inspectorの『Volume』で音量を調整できます。変えたら、もう一度再生して確認しましょう。」 |
| 7 | （任意）`Tools > D-Drive > Editors > Audio` を開き、対象にこの SE を設定、波形を表示 | Audio Editor の波形 | 「もっと細かく波形を見ながら調整したいときは、Audio Editorを使います。」 |

**締めの一言（ナレーション例）**: 「これで効果音の登録は完了です。ファイル名や保存場所は自動で決まるので、表示名と識別子の入力だけを覚えておいてください。」

## 2. 動画②: VFX を置いて位置を調整する（目安 5分）

**目的**: VFX Editor で確認用シーンを開き、Anchor（出す位置）とパラメータをその場で調整する様子を見せる。

- 開くシーン: 任意（カット2でVFX確認用シーンに切り替える）
- 用意する素材: 既存の VFX データ（例: `VFX_Player_Slash` のようなデモ用アセットが既にあればそれを使う。無ければ収録前に Asset Browser の「新規」で1つ作り、パーティクルのPrefabを割り当てておく）

| カット | 画面操作 | 映すもの | ナレーション原稿 |
|---|---|---|---|
| 1 | `Tools > D-Drive > Editors > VFX` を開き、対象アセット欄にVFXデータを設定 | VFX Editor 全体、対象アセット欄 | 「エフェクトの調整はVFX Editorで行います。対象アセットに、調整したいVFXデータを入れます。」 |
| 2 | ツールバーの「確認用シーンを開く」を押す | ボタンを押す操作、シーンが切り替わる様子 | 「エフェクトは今開いているシーンの中に出るので、最初に『確認用シーンを開く』を押します。ライトやカメラが揃った専用のシーンが開きます。」 |
| 3 | 「▶ 再生」を押す | SceneView に出るエフェクト | 「再生ボタンを押すと、その場でエフェクトが再生されます。ゲームを実行する必要はありません。」 |
| 4 | Anchor欄の「高さオフセット(Y)」スライダーを動かす、続いて2Dパッドをドラッグ | スライダーの動き、SceneView内でエフェクトが動く様子 | 「Anchorの項目で、エフェクトを出す位置を調整できます。再生中に動かすと、その場でエフェクトが動くのが分かります。」 |
| 5 | パラメータ欄で色（Color）を変更 | パラメータのカラーピッカー、エフェクトの色が変わる様子 | 「VFXデータで公開したパラメータは、再生中でもその場で反映されます。ここで変えた値はデータの既定値として保存されます。」 |

**締めの一言**: 「VFX EditorはウィンドウのようにVFXを表示していますが、実際にはシーンの中で実際のマネージャーが再生しています。だからここで確認した見た目と、実際のゲーム中の見た目は同じになります。」

## 3. 動画③: Presentation で剣攻撃を組む（目安 8分）

**目的**: 複数のアセット（アニメ相当の VFX/SE・カメラ揺れ・振動・ヒットストップ）を1つの演出にまとめる、D-Driveの目玉機能を見せる。

**参照ページ**: [presentation.html](DesignerManual/presentation.html) / [camera-haptics.html](DesignerManual/camera-haptics.html)

**事前準備**:
- 開くシーン: `Assets/GameData/PreviewScenes/PresentationSkillSlashPreviewScene.unity`（既存のデモシーン。まずこれで完成形を体験してから、新規に組む手順を見せる構成にする）
- 用意する素材: 収録用の SE・VFX（動画①②で作ったものを使い回してよい）、カメラシェイク・振動データが既にあれば使う（無い場合はそのトラックは省略してよい）

| カット | 画面操作 | 映すもの | ナレーション原稿 |
|---|---|---|---|
| 1 | `PresentationSkillSlashPreviewScene.unity` を開き Play、Pキーで再生・Spaceキーで「当たった」合図 | ゲーム再生、エフェクト・カメラ揺れ・画面停止 | 「これが『演出（Presentation）』のデモです。攻撃のアニメーション・効果音・エフェクト・カメラの揺れ・当たった時の画面停止が、全部1つのデータにまとまっています。今日はこれを自分で組んでみましょう。」 |
| 2 | Playを止め、`Tools > D-Drive > Presentation Editor` を開く（Toolsメニューの最上段にある） | メニューの位置、Presentation Editor 全体 | 「Presentation Editorは、目玉機能なのでToolsメニューの一番上にあります。」 |
| 3 | 「＋ 新規作成」で新しいPresentationデータを作成（表示名: 「剣攻撃(収録用)」、識別子: `TutorialSlash`） | 新規作成ダイアログ | 「対象アセット欄の隣にある『＋ 新規作成』から、その場で新しいPresentationを作れます。」 |
| 4 | Asset Browser や Project ウィンドウから SE データをタイムラインへドラッグ＆ドロップ | ドラッグ、Se用レーンにトラックが追加される様子 | 「タイムラインに、SEやVFXのデータを直接ドラッグ＆ドロップすると、種類に応じたトラックが自動で追加されます。」 |
| 5 | 同様にVFXデータをドラッグ＆ドロップ、時刻を少し右にドラッグして調整 | VFXトラックの追加、マーカーのドラッグ | 「時刻は落とした位置がそのまま入りますが、あとからドラッグで調整できます。」 |
| 6 | 「＋ トラックを追加」からKind=HitStopのトラックを追加し、Paramsに秒数（例: 0.1）を入力 | トラック追加、Params欄への入力 | 「手入力で追加したいときは『トラックを追加』からKindを選びます。ヒットストップは、当たった瞬間に一瞬時間を止める演出で、止める秒数をParamsに入れます。」 |
| 7 | Kind=Signal のトラックを追加し、Signal Keyに `hit` と入力し、Triggerを「On Signal」にする | Signal Key欄、Trigger切り替え | 「『当たった』という合図が来たときに鳴らしたい場合は、TriggerをOn Signalにして、合図の名前をSignal Keyに入れます。」 |
| 8 | 共通設定の「トラックの最後に合わせる」ボタンを押す | Total Durationの値が更新される様子 | 「全体の長さ(Total Duration)は、このボタンで各トラックの終わりに自動で合わせられます。」 |
| 9 | 「モデル選択」でモデルを選び「配置」、「▶ 再生」を押す | 確認用シーンにモデルが出て、再生される様子 | 「モデルを配置すると、そのモデルを起点にアニメ・SE・エフェクト・カメラの揺れが同時に再生されて確認できます。」 |
| 10 | 再生中に「Signalレーン」に出るボタン（`hit`）を押す | Signalボタンを押す、画面停止やエフェクトが起きる様子 | 「再生中にこのボタンを押すと、プログラム側から『当たった』という合図が来たのと同じ動きを試せます。」 |
| 11 | 保存し、Validation欄でErrorが無いことを確認 | 検証欄 | 「保存すれば、コードの変更なしにゲーム内の演出に反映されます。」 |

**締めの一言**: 「プログラマーはこの演出をコード1行、`Presentation.Play`で呼び出すだけです。中身はいつでもここで調整できます。」

## 4. 動画④: 発注ツールで発注してからインポート済まで（目安 5分）

**目的**: 企画が発注ツール（ブラウザ）に発注を登録 → D-Drive側にPlaceholderができる → デザイナーが中身を作る → 発注ツールの状態が自動で「インポート済」に進む、という一連の流れを見せる。

**参照ページ**: [spec-sync.html](DesignerManual/spec-sync.html) / [asset-browser.html](DesignerManual/asset-browser.html)

**事前準備**:
- 発注ツールの練習用アカウント（本番の企画メンバーの実名・実メールを映さないダミーのログイン、または画面共有時にメールアドレス部分を隠す準備）
- D-Drive側の `Tools > D-Drive > 仕様書と同期` の設定（Web API URL・トークン）は事前に設定済みにしておき、**収録中は設定欄を開かない**（映さない）
- 発注ツール側に、収録用のダミー発注を1件登録する練習をしておく（種別: Se、識別子: 例 `TutorialOrderSe`、表示名: 「収録用発注サンプル」）

| カット | 画面操作 | 映すもの | ナレーション原稿 |
|---|---|---|---|
| 1 | ブラウザで発注ツールを開き、「発注ツリー」または「一覧」から「新規」 | 発注ツールの画面（URLバーは映さない） | 「発注ツールは、企画・デザイナー・プログラマーが『誰が・何を・いつまでに作るか』をやり取りするためのWebアプリです。」 |
| 2 | 種別=Se、カテゴリ・識別子・表示名・発注者・受注者・納品期限を入力して作成 | 発注フォームの入力 | 「種類と識別子、表示名、発注者・受注者を入力して発注を1件作ります。」 |
| 3 | Unity側に切り替え、`Tools > D-Drive > 仕様書と同期` を開く（設定欄は映さず「取得」ボタンだけを操作） | 同期ウィンドウ、「取得」ボタン | 「Unity側では『仕様書と同期』ウィンドウで、発注ツールの内容を取得します。」 |
| 4 | 「取得」を押し、「新規」に出た行を確認、チェックを付けたまま「適用」を押す | 差分プレビューの「新規」行、適用ボタン | 「新規に出てきた行にチェックが付いていることを確認して、適用を押します。これで、D-Drive側にPlaceholder、つまり空のデータができます。」 |
| 5 | `Tools > D-Drive > Asset Browser` を開き、いま作られたSeデータを選ぶ | Asset Browserの一覧、新しい行 | 「Asset Browserを見ると、さっきの発注と同じ識別子のデータが、もう登録されています。」 |
| 6 | 音声ファイルをドラッグ＆ドロップ、または Clips に設定して中身を作り込む（動画①と同様の手順を簡略に） | Clips欄への設定 | 「あとは、いつも通りAsset Browserや専用エディタで中身を作り込みます。」 |
| 7 | `Tools > D-Drive > Validation > Run All` を実行し、Errorが無いことを確認 | Validation結果 | 「Validationでエラーが無い状態にします。」 |
| 8 | もう一度「仕様書と同期」を開き「取得」→「Web に送信」を押す | 同期ウィンドウ | 「もう一度同期すると、D-Drive側の状態が発注ツールに伝わります。」 |
| 9 | ブラウザに戻り、その発注の詳細を開いて状態が「インポート済」になっていることを確認 | 発注ツールの状態表示 | 「発注ツール側を見ると、状態が自動で『インポート済』に進んでいます。これは手動では選べない項目で、D-Drive側でエラーが無くなったことが確認できたときだけ、自動で進みます。」 |

**締めの一言**: 「発注した企画側は、Unityを開かなくても『インポート済』になったことがブラウザで分かります。」

## 5. 動画⑤: Validation で赤を直す（目安 3分）

**目的**: 「ゲームで出てこない・ピンク色になる」といったトラブルの原因を、Validationで見つけて直す一連の操作を見せる。

**参照ページ**: [validation.html](DesignerManual/validation.html)

**事前準備**:
- 収録用に、あえて設定ミスを1〜2件作った練習用データを用意する（例: Mixerを未割当のまま保存したSE、Prefabが未設定のVFX）。本番データには絶対に手を入れない

| カット | 画面操作 | 映すもの | ナレーション原稿 |
|---|---|---|---|
| 1 | 練習用データが赤く（Errorの状態で）存在するところから開始。`Tools > D-Drive > Validation > Run All` を実行 | メニュー操作、結果一覧 | 「ゲームで音が鳴らない、エフェクトがピンク色になる、といったときは、まずValidationを実行します。」 |
| 2 | 結果一覧でErrorの行（赤）を確認し、内容を読む（例: 「Mixerが未割当」） | Error行の文言 | 「赤い表示はError、つまりそのままだと動かない設定ミスです。文章を読めば、何が原因か分かるようになっています。」 |
| 3 | 対象データをAsset Browserで開き、Mixerを設定する | Inspectorでの設定操作 | 「今回はMixerが未設定でした。Inspectorから、サウンド担当が指定したグループを設定します。」 |
| 4 | もう一度 Run All を実行し、Errorが消えたことを確認 | 再実行、結果 | 「もう一度確認すると、Errorが消えています。」 |
| 5 | （別の例として）Prefab未設定のVFXを開き、「修正」ボタンが出る項目があれば押して直す | 「修正」ボタンをクリック | 「自動で直せる項目には『修正』ボタンが出ます。押すだけで直り、Ctrl+Zで元に戻せます。」 |

**締めの一言**: 「赤（Error）は必ず直す、黄色（Warning）は内容を読んで判断、青（Info）は読んでおくだけでOKです。困ったら、まずRun Allを実行する習慣をつけてください。」

## 6. 収録後にやること（人の作業のチェックリスト）

- [ ] 各動画から、収録用に作ったダミーデータ（SE/VFX/Presentation/発注）を削除またはArchiveする
- [ ] 動画に個人情報・URL・トークンが映っていないか通し確認する（§0.3）
- [ ] 書き出した動画ファイルを、チームで決めた場所（社内共有ドライブ等。このdocsにはURLを書かない）に置く
- [ ] [DesignerManual/Readme.html](DesignerManual/Readme.html) から動画への導線が必要ならページを追記する（動画のホスティング先が決まってから、別チケットで対応）
