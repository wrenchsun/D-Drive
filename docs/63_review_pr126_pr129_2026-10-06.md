### GE-R-01. 【#129 GD-R-01 の残り】Timeline ウィンドウでプレビュー用 Director を開いている間にシーンを保存すると、カットシーンの姿勢が保存されうる

- **場所**: `Editor/Cutscene/CutsceneEditModePreviewProvider.cs:311-325`（`origin/fix/review-62-editor-findings`）、`Editor/Cutscene/CutsceneEditModeCameraWriter.cs:48, 60-73`
- **細部**: 書くのを「開いている間」に絞ったので [62] の筋書き（閉じた後の保存）は消えたが、開いたままカメラクリップの区間内で Ctrl+S すると、その時点の姿勢で `Camera.main` が保存される（`EditorSceneManager.sceneSaving` での一時復元が無い。Canvas の Idle は `prefabSaving` で戻している）。シーンが dirty でなければ保存されないので、他の変更と一緒に保存したときに限る。あわせて、書いている途中で `Camera.main` が別のカメラに替わると（タグの付け替え・カメラの追加）、`CaptureIfNeeded` は前のカメラを戻さずに新しいカメラを控え直す（前のカメラはカットシーンの姿勢のまま残る。既存の細部）。
- **直し方の案**: `EditorSceneManager.sceneSaving` で `ResetCapture()`（次の更新で控え直して書き直される）。`CaptureIfNeeded` で `_capturedCamera != cam` のときは先に `ResetCapture()` を呼ぶ。
- **確度**: コード読みで確認。保存のときにシーンが dirty かどうかは**推定**。

### GE-R-03. 【#129 GD-R-08】要約の「変更なし」は Common の差分だけで決まり、その後のシェーダーの寄せ・固有の引き継ぎで既存 Data を書き換えても「変更なし」に数える

### 確認して問題なしだった観点

- **深さ 8 の整合**: 実行時は Open した CanvasData を `Depth = 1` とし、`node.Depth >= 8` の段では子を処理しない → 埋め込みは最大 7 段。Editor の `CollectWireStages`（`depth < 8` で最大 8 段）と #133 の `CollectEmbedPaths`（`depth >= 8` で打ち切り = 最大 8 段）は**同じ 8 段で互いに一致**し、どちらも実行時より 1 段深いところまで見る。8 段目は実行時に「入れ子が深すぎます」の警告でスキップされる段で、そこまでトリガーを避けたり None の注意を出したりしても安全側（配線を誤って止めることは無い）。実害が無いので指摘にはしない（揃えるなら `UiManager.MaxEmbedDepth` と同じ値の定数を Editor 側で 1 か所に持つ）。
- **入れ子の入れ子で実行時と欄が一致するか**: `HasEmbed` / `CollectEmbedPaths`（[65] GG-R-07）と `CollectWireStages` は、どちらも直下の登録の `RootPath` を結合して内側へ進む形で、実行時の `childPrefix`（`EmbeddedCanvasPaths.Combine(node.Prefix, embed.RootPath)`）と同じパスを作る。`EmbeddedRootPath` の解決（`OptionRoot/Inner`）と欄の選択肢・トリガーの回避は同じ段を見ている。`DescribeProblem` は `EmbeddedRootPath` の未登録の注意が None の注意より先なので、#133 の注意を隠さない。
- **循環**: `CollectWireStages` は `child == current` と「既に集めた段にある」で止めるが、最初の `canvas` 自身は `into` に入らないので、A → B → A では A が 1 回だけ段に入る（3 段目の B で止まる）。実行時は `ChainContains` でその段をスキップする。循環は別途 Validation の対象で、余分に避けるだけの安全側なので問題なし。
- **`TryFirstFreeTrigger` の空きなし**: 全段 + 親のトリガーが 4 つとも埋まっていれば `AddWire` が `Undo.RecordObject` の前に -1 で抜ける（空の Undo を積まない）= 従来どおり。
