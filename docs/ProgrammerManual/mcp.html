AI エージェント連携（D-Drive MCP）

最終更新日: 2026-10-07

D-Drive の Editor 機能（Data の作成・値の変更・検査・生成・マイグレーション・確認用シーン・リリース前チェック）を、AI エージェント（Claude Code など）が MCP ツール ddrive_* として直接呼べる仕組みです（v1.5.0）。execute_code で C# を書かなくても、1 回のツール呼び出しで 1 つの操作が終わります。返り値は件数と要点だけに絞ってあり、AI が使うトークンは少なくなります。

サーバーは Editor 組み込みの jp.shiranui-isuzu.unity-mcp（isuzu 版）を使います。D-Drive が持つのはツール本体（Packages/com.ddrive.core/Editor/Mcp/、asmdef DDrive.Editor.Mcp）だけで、既存の Editor サービスを呼ぶ薄いアダプタです。isuzu 版のパッケージが入っていないプロジェクトでは、この asmdef はコンパイルされません（何も増えません）。設計・経緯・計測結果は docs/1002_ddrive_mcp.md にあります。

コンパイル・テストの確認は従来どおり isuzu の compile_request / compile_status / test_run / test_results で行います。ddrive_* は D-Drive の操作（Data・検査・生成・確認用シーンなど）を担当します。

セットアップ

  1. Packages/manifest.json に jp.shiranui-isuzu.unity-mcp（v4.2.0 以上）が入っていること。入っていなければ Tools > D-Drive > Update > 更新ウィンドウ の「Unity MCP（isuzu）」の「導入」（またはセットアップウィザードの「AI 連携（MCP）」）で入れます。推奨版のタグ固定で追加し、更新ウィンドウの管理対象に登録します。CoplayDev 等の他の MCP が入っていれば確認ダイアログが出ます（CoplayDev は「外して続行」できます。.mcp.json に残った設定は手で消してください）。Unity を開くとサーバーが自動で起動します（Preferences > Unity MCP で確認できます）
  2. プロジェクト直下で pwsh Tools/Mcp/register-mcp.ps1 を実行します（更新ウィンドウで導入した直後の案内パネルの「登録スクリプトを実行」でも同じです。パッケージ導入先では Packages/com.ddrive.core/Tools~/Mcp/register-mcp.ps1 -ProjectPath <プロジェクト>）。Unity が書く接続情報（%LOCALAPPDATA%\UnityMCP\instances\<hash>.json）を読み、生存を確認して claude mcp add で登録し直します。-Print は接続情報の確認だけ、-DryRun は実行するコマンドの確認だけです
  3. Claude Code を開き直し、claude mcp list で isuzu-unity ✓ Connected を確認します。Unity を再起動してトークンが変わったときは、1. をやり直す必要はなく register-mcp.ps1 をもう一度実行します
  4. 最初に ddrive_help（topic=rules）と ddrive_status を呼ぶと、禁止事項の要約と現状（コンパイル・検査・マイグレーション・書き込み許可）が分かります

ポートは自動です。プロジェクトのパスから 27200〜27999 のポートが決まり、別のプロジェクト（MS2026 など）を同時に開いても重なりません。Preferences > Unity MCP でポートを固定すると他と衝突しやすくなるため、固定しないでください（固定すると Validation の Info DD-MCP-FIXED-PORT と ddrive_status の警告が出ます）。ポート番号をスクリプトや docs に直書きせず、接続先は常に接続情報から読みます。

書き込みを許可する設定

Project Settings > D-Drive > MCP の「MCP の書き込みツールを許可する」（DDriveProjectSettings.McpAllowWrite）が ON のときだけ、書き込みを伴うツールが動きます。既定は OFF（持ち込み先で勝手に Data が書き換わらないため）。同じチェックボックスがセットアップウィザードの「4. 既定フォルダ・設定の生成」にもあります。OFF のときは書き込みツールが {"error":{"code":"write_disabled"}} を返し、何も変更しません。読み取りだけのツールは OFF でも使えます。

ツール一覧（20 個）

凡例: R = 読み取りのみ / W = 書き込み（McpAllowWrite が必要）/ D = Destructive（W に加えて confirm:true が必要）。ID は JSON では 10 進の文字列（"id":"1234567890123"）で、0x 付きの 16 進文字列も受けます。長い一覧は limit / cursor（返り値の next を渡す）と max_chars（既定 4000、上限 16000）で収まります。

状態・案内

ツール種別内容
ddrive_statusRバージョン・スキーマ・コンパイル・直近のテスト・検査の要約・未適用マイグレーション・Addressables 未登録・MCP の状態（sections で絞れます）
ddrive_helpR短い案内カード。topic = rules / types / menu / tool:<名前> / validation:<Code>
// ddrive_status
{ "sections": "version,mcp" }
// → { "version": "...", "mcp": { "writeEnabled": true, "port": ..., "portMismatch": false, ... } }

// ddrive_help
{ "topic": "validation:DD-ADDR-CATALOG-MISSING" }

Data

ツール種別内容
ddrive_asset_listR種別（type）ごとの一覧。category / query（表示名・識別子の部分一致）/ fields で絞り込み
ddrive_asset_getR1 件の欄の値と検査件数。fields 省略は共通欄 + 種別の主要欄、"*" で全欄
ddrive_asset_createW新規作成。命名・置き場所・カタログ・Addressables 登録まで 1 回で行い、検査件数を返す。preview あり
ddrive_asset_setW欄の値を変更。全欄が書けるときだけ書く。preview あり
ddrive_editor_openR種別の専用エディタを開く（人が見るため）
// ddrive_asset_create（まず preview で確認）
{ "type": "Se", "name": "Player Slash", "category": "Player", "preview": true }
// → { "wouldCreate": "Assets/GameData/.../....asset", "identifier": "PlayerSlash" }

// ddrive_asset_set（欄名はシリアライズ名。入れ子はドット区切り、配列は全体置換）
{ "type": "Se", "id": "1234567890123", "fields": { "Description": "斬撃音" } }
// → { "changed": [ { "field": "Description", "from": "", "to": "斬撃音" } ], "validation": { "errors": 0, "warnings": 0 } }

変更した欄の ChangeNote には AI の変更だと分かるよう [mcp] が先頭に付きます。型ごとの欄の一覧は ddrive_help と docs/1002_ddrive_mcp.md §4.5 にあります。

依存・削除

ツール種別内容
ddrive_asset_usagesRその ID の参照元（シーン・Prefab・Timeline・他の Data）
ddrive_asset_unusedRどこからも参照されていない Data（archived の印つき）
ddrive_asset_deleteD参照もコード参照も無い Data の削除。preview は分析だけ

依存グラフが未構築のときは、これらは {"needsRebuild":true} を返します（ddrive_generate の kind=deps で構築します）。参照されている Data は削除できず、blockers に参照元が並びます。

// ddrive_asset_delete（分析だけ）
{ "type": "Se", "id": "1234567890123", "preview": true, "confirm": true }
// → { "path": "...", "wouldDelete": true, "blockerCount": 0 }

検査

ツール種別内容
ddrive_validateR検査。scope = all / project / type:<種別> / asset:<種別>:<id>。detail = summary（既定。件数と Code 別の表）/ errors / all
ddrive_validate_fixD自動修正（FixAction を持つ指摘だけ）。preview で件数だけ確認
ddrive_forbidden_apiR禁止 API の走査（規則別の件数と該当行）
// ddrive_validate
{ "scope": "type:Se", "detail": "errors", "limit": 20 }
// → { "scope": "type:Se", "errors": 1, "warnings": 3, "byCode": [ { "code": "DD-...", "sev": "Error", "count": 1 }, ... ], "items": [ ... ] }

生成・更新

ツール種別内容
ddrive_generateWkind = ids（ID 定数）/ tuning / addressables（同期）/ preload / prefabs / deps（依存グラフ）/ icons。preview あり（意味は kind ごと）
ddrive_migrateDmode = plan（既定。未適用の一覧）/ apply（適用。書き込み許可が必要）
ddrive_compatR互換性スナップショット 7 種の差分。削除された行があれば warning
ddrive_compat_updateDスナップショットを現在の形に更新（意図した追加のときだけ）
ddrive_release_checkRTools/Release/check-release.ps1 の結果（base = 比較するタグ、guard_only）
// ddrive_generate
{ "kind": "ids", "preview": true }
// → { "target": "ids", "preview": true, ... }（何も書かれません）

// ddrive_migrate（計画だけ。Destructive のツールなので confirm が要る）
{ "mode": "plan", "confirm": true }

プレビュー・ビルド

ツール種別内容
ddrive_previewW（status は R）action = open（確認用シーンを開く。scene = common / canvas / cutscene / shake）/ play / stop / stop_all / sweep（孤児の掃除）/ status
ddrive_build_netcheckWNetCheck の Windows ビルド（Builds/DDriveNetCheck）。1〜3 分かかる同期実行で、isuzu が自動でジョブ化します（job_status で結果を取る）
// ddrive_preview（確認用シーンを開き、VFX を置いて再生）
{ "action": "open", "scene": "common", "type": "Vfx", "id": "1234567890123" }
// → { "scene": "common", "placed": "[D-Drive] VFX Preview", "handle": "1" }

// ddrive_preview（SE を鳴らす → 止める）
{ "action": "play", "type": "Se", "id": "1234567890123" }
{ "action": "stop", "handle": "1" }

再生は各エディタが使うのと同じ 実 Manager で行います（Editor 専用の再生経路はありません）。play の対象は Se / Bgm / Vfx / Presentation で、それ以外の種別は ddrive_editor_open で専用エディタを開いてください。open は、保存確認のダイアログを出さない代わりに、未保存のシーンがあると何も開かず {"blocked":"unsaved scene"} を返します。

安全装置

仕組み内容
previewasset_create / asset_set / asset_delete / generate / validate_fix は preview:true で、何も書かずに「こうなる」だけを返します
confirmddrive_asset_delete / ddrive_validate_fix / ddrive_migrate / ddrive_compat_update は confirm:true が無いと confirmation_required を返して実行しません
Undo と保存Data の変更は Undo.RecordObject + EditorUtility.SetDirty + 保存フック経由で、人が Inspector で編集したのと同じ扱いです
読み取り専用欄Id / SchemaVersion / ImportSourceGuid / Version / UpdatedAt / Icon は read_only_field で拒否されます。YAML や .meta を直接触るツールはありません
Play ModePlay Mode 中の書き込みは play_mode で拒否されます（変更が破棄されるため）。読み取りは使えます
例外例外はスタックトレースを返さず {"error":{"code":"...","msg":"..."}} の 1 行にまとめます。コードは play_mode / write_disabled / read_only_field / invalid_params / exception

互換性（追加のみ）

ツール名・引数名と型・Destructive かどうか・返り値のキー・ddrive_help の topic 名は契約で、追加だけが許されます（削除・改名・型変更は MAJOR）。Packages/com.ddrive.core/Tests/Editor/Compat/Snapshots/mcp-tools.txt が現在の一覧で、McpToolsSnapshotTests が完全一致で検査します（docs/42_distribution.md §5.14 E-24）。ツールの上限は 20 個で、機能を足すときは既存ツールの引数に足します。

持ち込み先が自分のツールを足すこともできます。自分の Editor asmdef に [McpTool("ms2026_xxx", ...)] を付けた static メソッドを書けば同じサーバーに載ります（接頭辞 ddrive_ は D-Drive が予約しています）。
