演出（Presentation）と Anchor / 配置セット

「剣攻撃」のようにアニメ・SE・VFX・カメラ揺れ・振動・ヒットストップをまとめて 1 つの演出として再生する仕組みが Presentation、演出やエフェクトを出す「位置」を扱う仕組みが Anchor（AnchorData）/ 配置セット（AnchorGroupData）です。演出データそのものの作り方（トラックの編集・専用エディタの使い方）はデザイナーマニュアル: 演出（Presentation）の設定項目を、Anchor の作り方はAnchor（出す位置）の作り方・配置セット（AnchorGroup）の作り方を先に読んでください。このページはプログラマーが書く側の API（Presentation / Anchors ファサードと PlayContext）だけを扱います。

実際のゲームコードは 1 行で足ります。 サンプル Packages/com.ddrive.core/Samples~/Demo/PresentationSkillSlashDemo.cs は DDrive.Samples.asmdef（DDrive.Runtime のみ参照）から生成コード（Assets/Generated/AssetIds.g.cs、asmdef 無し = Assembly-CSharp 所属）の PRESENTID.DemoSkillSlash を直接参照できないため、同じ値を生の AssetId として組み立てています（19 行目付近のコメント参照）。あなたが Assembly-CSharp 側に書くゲームコードでは次の 1 行で足ります。 
Presentation.Play(DDrive.Generated.PRESENTID.DemoSkillSlash, ctx);

Presentation 静的ファサード

Runtime/Presentation/Presentation.cs。他の種別（Vfx / Anim 等）と同じ ADR#3 の薄いファサード設計です。Bind() 前・未 Bind 中の呼び出しはすべて no-op（Invalid Handle を返すか何もしない）で継続し、例外は投げません。

public static class Presentation
{
    public static void Bind(PresentationManager instance);
    public static bool IsBound { get; }

    public static PresentationHandle Play(PresentationId id, in PlayContext ctx);
    public static PresentationHandle PlayData(PresentationData data, in PlayContext ctx);

    // ── Handle 操作(PresentationHandle からも同じ内容を呼べる) ──
    public static void Signal(Handle<PresentationMarker> h, string key);
    public static void Cancel(Handle<PresentationMarker> h);
    public static void Pause(Handle<PresentationMarker> h);
    public static void Resume(Handle<PresentationMarker> h);
    public static void SetSpeed(Handle<PresentationMarker> h, float speed);
    public static void Seek(Handle<PresentationMarker> h, float time);
    public static bool IsPlaying(Handle<PresentationMarker> h);
    public static float NormalizedTime(Handle<PresentationMarker> h);   // 無効なら -1

    public static Observable<Unit> OnCompleted(Handle<PresentationMarker> h);
    public static Observable<Unit> OnCancelled(Handle<PresentationMarker> h);
    public static Observable<string> OnMarker(Handle<PresentationMarker> h);
    public static Observable<PresentationTrack> OnTrackFired(Handle<PresentationMarker> h);
    public static UniTask WaitAsync(Handle<PresentationMarker> h, CancellationToken ct = default);
}

PresentationId は AssetId<PresentationMarker> のエイリアスです。Play / PlayData の戻り値 PresentationHandle は Handle<PresentationMarker> を薄くラップした専用 struct で、上の Handle 操作メソッドと同じ内容をプロパティ・メソッドとして直接呼べます。詳しくはHandle・イベント・完了待ちを参照してください。

メソッド備考
Play(id, ctx)ID から PresentationData を解決して再生。未登録 ID は Placeholder で継続
PlayData(data, ctx)すでに手元にある PresentationData を直接再生（エディタのプレビュー等が使う）
Cancel(h)全トラック停止。PresentationData.Interruptible=false のときは警告 + no-op（止まらない）
Pause / Resume内部的には SetPaused(h, true/false)
Seek(h, time)デバッグ・スキップ用。表示専用の DisplayDuration ではなく実際の再生尺（PresentationTiming.EffectiveDuration）にクランプされる

PlayContext

Runtime/Presentation/PlayContext.cs。Presentation.Play / PlayData に in 渡しする再生文脈です。

public struct PlayContext
{
    public Transform Self;         // 再生主体(プレイヤー等)。Target=Self のトラックの基準
    public Transform Target;       // 対象(敵等)。null 可。Target=ContextTarget のトラックの基準
    public Vector3 Position;       // 発生位置
    public Action<string> OnSignal; // 演出→ゲームコードへの通知(Kind=Signal のトラックから呼ばれる)
}

各フィールドの既定値・null 時の挙動（実装 PresentationManager.ResolveContextRoot / FireVfx 等で確認済み）:

フィールド既定値 / null のときの挙動
SelfTrackTargetMode.Self のトラックが基準にする Transform。null でも Play() 自体は呼べる（World/Anchor 基準のトラックや Marker/Signal/HitStop だけの演出はモデル不要）。Self 基準の Vfx/Se/Anim/Anim2D/UiTween トラックは「Animator が見つかりません」等の警告 1 回 + no-op で個別にスキップされ、演出全体は止まらない
TargetTrackTargetMode.ContextTarget の基準。null なら同様に該当トラックだけ警告 + no-op
Position既定 Vector3.zero。Vfx/Se トラックの位置解決には使われない（Target=World/Anchor は contextRoot=null で AnchorDef.LocalOffset をそのまま絶対座標として使う）。CameraShake / Haptic トラックには発生位置としてそのまま渡る（ShakeSpace.FromSource 用、docs/08 5-2 実装メモ）
OnSignal既定 null。Kind=Signal のトラックが発火するとき instance.Ctx.OnSignal?.Invoke(track.SignalKey) と null 条件演算子で呼ばれるだけなので、未設定でも例外にはならず、その通知は単に届かない

実行モデル

Presentation.Play(id, ctx) → PresentationHandle
  ├ AtTime(0.00) トラック → Play() 呼び出し中に同期的に発火
  ├ AtTime(t)    トラック → Tick でスケジュール実行
  └ OnSignal("hit") トラック → handle.Signal("hit") が来たら実行

Presentation 自身は再生処理を持たず、各 Manager（Anim/Se/Bgm/Vfx/Canvas/UiTween/CameraShake/Haptic）への委譲だけを行う薄いオーケストレータです（Timeline トラックのみ未実装で警告 + no-op）。

AtTime(0.00) は Play() 呼び出し中に同期発火します。 そのため var h = Presentation.Play(id, ctx); h.OnMarker.Subscribe(...) のように Handle を受け取ってから購読しても、Time=0 のトラックは観測できません（docs/08_presentation.md 実装メモ）。Time=0 の通知を確実に受け取りたい場合は下記の PlayContext.OnSignal（Kind=Signal）を使ってください。

ゲームコードとの双方向通知

演出データとゲームコードの間には向きの異なる 3 つの経路があります。SignalKey（デザイナーがトラックに付ける文字列）を名前として使い回している点は共通ですが、意味は別なので混同しないでください。

経路向きトリガー
handle.Signal(key)（= Presentation.Signal(h, key)）ゲームコード → 演出データ当たり判定等が成立したタイミングでコードから呼ぶ。Trigger=OnSignal かつ SignalKey が一致するトラックがそこで初めて発火する（1 トラックにつき最大 1 回）
handle.OnMarker（Observable<string>）演出データ → ゲームコードKind=Marker のトラックがタイムライン上のその時刻・Signal に到達すると SignalKey を積んで OnNext する。「演出の山でダメージ数値を出す」等、見た目には何も起きない目印をコード側が購読する用途
ctx.OnSignal（Action<string>）演出データ → ゲームコードKind=Signal のトラックが発火すると ctx.OnSignal?.Invoke(track.SignalKey) が呼ばれる。OnMarker と役割は似ているが、Observable の購読ではなく PlayContext に渡したコールバックが直接呼ばれる点が違う（Time=0 でも確実に受け取れる。上の警告参照）

剣攻撃デモ（PRES_Demo_SkillSlash.asset）は AtTime(0.00) に Vfx+Se、OnSignal("hit") に HitStop(0.08s)+Se を配置しています。実際のコード側（Packages/com.ddrive.core/Samples~/Demo/PresentationSkillSlashDemo.cs）は次のように書きます。

private PresentationHandle _handle;

public void Play()
{
    _handle = Presentation.Play(SkillSlashId, new PlayContext { Self = self, Position = self.position });
}

public void TriggerHit()
{
    // 当たり判定が成立した瞬間にコードから呼ぶ → OnSignal("hit") トラック(HitStop+SE)が発火する
    _handle.Signal("hit");
}

public void CancelPresentation()
{
    _handle.Cancel();
}

Anchor / 配置セット

VFX/SE を「どこに」出すかを表す単位が AnchorData（1 つの位置）、複数の位置へ一括で出す単位が AnchorGroupData（配置セット）です。仕様は docs/21_anchor_spec.md・docs/22_anchor_group.md、作り方はデザイナーマニュアル: Anchor・配置セットを参照してください。ここではプログラマーがコードから触る部分だけを説明します。

Anchors 静的ファサード（配置セットの再生）

Runtime/Anchoring/AnchorGroupPlayer.cs:226-243。Presentation がトラック種別 AnchorGroup を持つまでの暫定 API で、他のファサードと同じ「未 Bind = no-op」設計です。

public static class Anchors
{
    public static void Bind(AnchorGroupPlayer instance);
    public static bool IsBound { get; }

    public static Handle<AnchorGroupMarker> Play(AnchorGroupId id);
    public static Handle<AnchorGroupMarker> Play(AnchorGroupId id, Transform contextRoot);
    public static void Stop(Handle<AnchorGroupMarker> h);
    public static void Kill(Handle<AnchorGroupMarker> h);
    public static bool IsPlaying(Handle<AnchorGroupMarker> h);
}
var h = Anchors.Play(ANCHORGROUPID.HealField, ctx.Self);
// 配置セットが定義する全点分の VFX/SE を VfxManager.SpawnData / AudioManager.PlaySeData でまとめて再生する
Anchors.Stop(h);   // フェードアウト等、通常の停止
Anchors.Kill(h);   // 即時停止
Anchors.IsPlaying(h); // 1 点でも再生中なら true

contextRoot は配置セットの原点（AnchorGroupData.OriginAnchorId / 埋め込み Origin）が Space=BoneName/NamedObject のときに、その名前をどの階層から検索するかの基準です。Stop / Kill はグループが出した VFX/SE をまとめて操作し、IsPlaying は 1 点でも再生中なら true を返します（内部の Handle リストはグループ終了時に自動で台帳から外れます）。

AnchorId をコードから指定する意味

VFX/SE 個別の Anchor 解決には、Data 側の設定を 呼び出し側から上書きできる優先順位があります（docs/21_anchor_spec.md §3.3）。

解決の優先順位(VFX/SE 共通):
  1. 呼び出し引数の anchorId          Vfx.Spawn(id, anchorId) / Vfx.Spawn(id, anchorId, contextRoot)
  2. 呼び出し引数の位置/Transform     従来どおり(Data を完全に上書き)
  3. Data.AnchorId (≠0)              AnchorData を Registry から解決
  4. Data.Anchor (埋め込み。旧形式)   従来どおり
  5. World 原点

つまり VfxData 側に AnchorData（例: Anchor_RightHand）を設定していても、コード側で別の AssetId<AnchorMarker> を明示的に渡せば、そちらが優先されます。「同じエフェクトを状況に応じて違う位置から出したい」といったケースで、Data を複製せずに済みます。

この優先順位は Vfx.Spawn(VfxId, AnchorId) / Vfx.Spawn(VfxId, AnchorId, Transform) のような個別呼び出しに対するものです。Presentation のトラック（PresentationTrack.Anchor）は埋め込みの AnchorDef と TrackTargetMode（Self/ContextTarget/World/Anchor）だけで基準を決めており、コード側から AnchorId で上書きする経路は現状ありません（PresentationManager.cs に AnchorId の参照は無いことを確認済み）。トラック単位で出す位置を変えたい場合は、デザイナーが PresentationEditor でトラックごとの Anchor を直接編集する形になります。
