新しい種別（AssetType）を追加する

D-Drive に新しいアセット種別（例: 新しい AssetType）を追加する手順をまとめます。設計上、拡張点（[AssetIdDefinition] 属性、IValidator の自動発見、[DataEditor] 属性）に載せることで、基盤（Foundation / Editor の生成器・発見ロジック）自体は無改修で新種別に対応できるように作られています（NFR-7）。このページのファイル一覧は、既存の Haptics 種別（AssetType.Haptics）を実際に grep して確認した実在ファイルです。

P-13（互換性ルール）発効後は AssetType の追加そのものに制約がかかります。（docs/42_distribution.md）配布用パッケージ化が完了し互換性ポリシーが発効すると、AssetType enum への追加・シリアライズ形式の変更は §5 の互換性ポリシーに従う必要があります。発効前の現時点では、このページの手順どおり進めて問題ありません。

手順の全体像

種別の追加とは別に、外部パッケージが D-Drive の取り込みへ後処理を足す拡張点があります（カットシーン取り込みリスナー）と、Timeline に外部のマーカーを置ける拡張点があります（カットシーン・マーカー）、「今どこから見ているか」を取り出す・差し替える口があります（現在の視点カメラ）。

1. AssetType enum への追加

Foundation/Identity/AssetType.cs の末尾に追記します。

public enum AssetType : byte
{
    None = 0,
    Se, Bgm, Vfx, Anim, Anim2D, Material, Texture, Canvas,
    Prefab, Presentation, Shake, Haptics, UiTween, Model,
    Anchor, AnchorGroup, ControlSkin,

    // 末尾に追加すること
    YourNewType,
}
既存の値を並び替えたり、途中に挿入してはいけません。 .asset の YAML には enum が整数値で永続化されるため、並び替え・挿入は既存アセットの種別を破壊します。必ず末尾に追記してください。

2. Data クラスと AssetIdDefinition 属性

AssetDataBase を継承した Data クラスに [AssetIdDefinition(AssetType, MarkerType, ConstantsClassName)] を付けます。HapticsData.cs の実例:

public readonly struct HapticMarker
{
}

[CreateAssetMenu(menuName = "D-Drive/Haptics/Haptics Data", fileName = "HAPTIC_NewHaptic")]
[AssetIdDefinition(AssetType.Haptics, typeof(HapticMarker), "HAPTICID")]
public class HapticsData : AssetDataBase
{
    // ... フィールド
}

MarkerType（例の HapticMarker）は Handle<T> と AssetId<T> の型引数に使う、中身のない struct です。型だけで種別を区別するための目印で、これがあることで「VFX の Handle に SE の ID を渡す」といった取り違えがコンパイルエラーになります。

3. ID 定数の生成（自動）

AssetIdGenerator は AppDomain.CurrentDomain.GetAssemblies() の全アセンブリ（DDrive.Tests.* は除く）を走査し、AssetDataBase を継承する具象クラスで [AssetIdDefinition] を持つものをリフレクションで自動発見します。生成器本体の改修は不要です。Tools > D-Drive > Generate > Regenerate Asset IDs（または CI の [2/6]）で HAPTICID のような定数クラスが自動生成されます。

4. 命名規則・配置フォルダの登録

Editor/AssetBrowser/AssetNamingService.cs の 2 つの switch 式に case を追加します。ここを忘れても例外にはなりませんが、既定値（接頭辞 "ASSET"、フォルダ "Misc"）に落ちてしまいます。

public static string GetTypePrefix(AssetType type) => type switch
{
    // ...既存
    AssetType.YourNewType => "YOURTYPE",
    _ => "ASSET",
};

public static string GetTargetFolder(AssetType type) => type switch
{
    // ...既存
    AssetType.YourNewType => "YourType",
    _ => "Misc",
};

5. 定数名生成の接頭辞（KnownPrefixes）

Editor/Codegen/AssetIdGenerator.cs の KnownPrefixes（HashSet<string>）に、手順4 で決めた接頭辞を追加します。ToConstantName がファイル名の先頭トークンをこの一覧と照合し、一致すれば定数名から取り除きます（例: HAPTIC_PlayerHit → HAPTICID.PlayerHit）。

ここへの登録を忘れると、接頭辞が二重に残った定数名になります。 例えば MODELID.MODELPlayerModel のように、種別プレフィックス（MODELID）とファイル名の接頭辞（MODEL）が両方残ってしまいます。現在の内容は KnownPrefixes = { "SE", "BGM", "VFX", "ANIM", "ANIM2D", "MAT", "TEX", "CANVAS", "PREFAB", "PRES", "SHAKE", "HAPTIC", "HAPTICS", "UITWEEN", "MODEL", "ANC", "ANCG", "SKIN", "CUT" }（19 個。Packages/com.ddrive.core/Editor/Codegen/AssetIdGenerator.cs）です。なお docs/42_distribution.md §5.3 により、互換性ポリシー発効（P-13）後は KnownPrefixes への追加は禁止になります。

6. カタログ割当

Editor/AssetBrowser/AssetCreationService.GetCatalogName(AssetType) に、新種別をどのカタログ（既存流用でも新規でも可）にまとめるかを追加します。

public static string GetCatalogName(AssetType type) => type switch
{
    // ...既存
    AssetType.Shake or AssetType.Haptics => "CameraFxCatalog",
    AssetType.YourNewType => "YourTypeCatalog",
    _ => "MiscCatalog",
};

同じメソッドの近くにある「Preload 強制」の分岐（AssetType.Canvas / ControlSkin / Presentation / Shake / Haptics）も確認してください。Manager が Play/Spawn 時に 同期解決（ResolveOrPlaceholder 等）しか使わない設計の場合、既定の LoadMode.LazyLoad のままだと「初回参照時にロード」が起きず常に Placeholder になる不具合があるため、その種別も LoadMode.Preload に追加する必要があります。

7. Manager

新しい XxxManager は Foundation/Manager/IAssetManager を実装します。

public interface IAssetManager
{
    AssetType Type { get; }
    void Tick(float dt);
    void OnPause(PauseChannel channel, bool paused);
    void StopAll(StopReason reason);
    void OnSceneUnload();
}

Manager を new するのは DDriveRuntimeBootstrap・テスト・Editor プレビューだけという規約があります（CLAUDE.md §0-8）。Manager は Data を書き換えません（読み取り専用）。Instance ごとの現在値は Instance 側に持たせます。

8. 静的ファサードと Handle マーカー型

Haptics.cs は薄い静的ファサードの典型例です。Bind 前の呼び出しは全て no-op（Invalid Handle）で継続します（例外で止めない設計、コーディング規約参照）。

public static class Haptics
{
    private static HapticsManager _instance;
    public static void Bind(HapticsManager instance) => _instance = instance;
    public static bool IsBound => _instance != null;

    public static Handle<HapticMarker> Play(HapticId id)
        => _instance?.Play(id) ?? Handle<HapticMarker>.Invalid;
    public static void Stop(Handle<HapticMarker> h) => _instance?.Stop(h);
    public static void StopAll() => _instance?.StopAll();
}

9. DDriveRuntimeBootstrap への配線

Runtime/Loop/DDriveRuntimeBootstrap.cs に、他の Manager と同じパターンで追加します。

Haptics = new HapticsManager(Registry);
// ...
loop.Register(Haptics);
// ...
Runtime.Haptics.Haptics.Bind(Haptics);
// (Shutdown 側)
loop.Unregister(Haptics);
Runtime.Haptics.Haptics.Bind(null);

ネット対応が必要な種別（Cosmetic/Simulated）は、Audio/Vfx/Prefabs/Presentation と同様にコンストラクタへ INetBridge netBridge = null を受け取れるようにします（詳細は ネットワーク（INetBridge / NGO））。

10. Validator

IValidator を実装するだけで、CI.DiscoverValidators()（AppDomain.CurrentDomain.GetAssemblies() を走査し、DDrive.Tests.* 以外のアセンブリから型を集める）が自動発見します。明示的な登録は不要です。

public interface IValidator
{
    AssetType Target { get; }
    IEnumerable<ValidationResult> Validate(AssetDataBase data, ValidationContext ctx);
}

11. 専用エディタ（DataEditor 属性）

デザイナーが編集する専用 EditorWindow がある場合、[DataEditor(typeof(XxxData), "…で開く")] を付けます（Editor/Inspector/DataEditorAttribute.cs）。CameraFxEditorWindow は 1 ウィンドウで 2 種別（Shake / Haptics）を扱うため属性を 2 つ付けている実例です。

[DataEditor(typeof(CameraShakeData), "Shake Editor で開く")]
[DataEditor(typeof(HapticsData), "Haptics Editor で開く")]
public class CameraFxEditorWindow : EditorWindow
{
    public static void Open(HapticsData data) { /* ... */ }
}

public static Open(XxxData)（引数型は基底 AssetDataBase でも可、メソッド名は属性の第 3 引数 openMethod で変更可、既定 "Open"）を DataEditorRegistry が TypeCache で拾い、Inspector 最上部の「エディターで開く」ボタンに自動で出ます。専用エディタを持たせない種別を作る場合は、Tests/Editor/DataEditorRegistryTests.cs の Exempt リストに理由付きで追加してください（このテストが「全 AssetDataBase 派生型に登録があるか」を検査し、付け忘れを検出します）。

12. Addressables / カタログ登録

手順6で GetCatalogName を設定していれば、デザイナーが Asset Browser や新規ダイアログでアセットを作成した時点で AssetCreationService.Create が自動的に RegisterToCatalog + AddressablesSync.EnsureEntry/EnsureCatalogEntry を呼び、カタログと Addressables への登録が完了します。プログラマー側で追加の手作業は不要です。CLAUDE.md §0-8 の「作成した Data は Addressables に同じ address で登録されていること」は Validation > Run All が機械的に検出します。

カットシーン取り込みリスナー（ICutsceneImportListener）

Maya の FBX から CutsceneData と .playable を作る取り込み（CutsceneImportService）が、ショット 1 つ分を作る・更新し終えるたびに、外部のコードへ知らせる拡張点です。取り込み後に .playable へトラックを足す、Bindings へ binding を追記する、といった後処理を、AssetPostprocessor の実行順に頼らず確実に D-Drive の取り込みの後で行えます（D-Drive の取り込みは EditorApplication.delayCall で後回しに走るため、postprocessOrder では順序を制御できません）。DDrive.Editor アセンブリを参照するエディタ用コードに書きます。

using DDrive.Editor.Cutscene;

public sealed class MyImportListener : ICutsceneImportListener
{
    public int Order => 100;   // 小さい順に呼ばれる（同値は型のフルネーム順）

    public void OnCutsceneShotImported(CutsceneImportResult result)
    {
        foreach (var role in result.Roles)
        {
            // role.RoleName = Bindings の TrackName、role.Kind = Camera / Prop / Character、
            // role.Track = 生成・更新したトラック、role.SourcePath = 元 FBX のパス
        }
        // result.Data（CutsceneData。Bindings に追記してよい）と result.Timeline（.playable）を書き換えてよい。
        // 保存は不要（全リスナーの呼び出しの後に D-Drive が 1 回保存します）。
    }
}
項目内容
発見TypeCache で自動。public な型（別の型の中に入れた型は、外側の型も public であること）と public な引数なしコンストラクタが必要（登録コードは不要）。名前が DDrive.Tests で始まるアセンブリの実装は除外されます
呼ばれるときFBX の自動取り込み、Tools > D-Drive > Generate > SourceAssets/Cutscene からインポートルールを再実行、CutsceneImportService.ProcessPaths / ScanAll のすべて。再取り込みのたびに毎回呼ばれます（result.IsNew が false）
引数 CutsceneImportResultShotName（ファイル名の <ショット> 部分）・Category・Data・Timeline・TimelinePath・IsNew・Roles
役 CutsceneImportRoleRoleName・ModelIdentifier（キャラのみ）・Kind・Track・SourcePath。アニメーションが無くトラックができなかった役は含まれません
例外リスナーごとに捕まえて Console に出し、他のリスナーと取り込みは続きます
重複させない再取り込みでは D-Drive が作ったトラックだけ更新し、既存の Bindings と足したトラックは残ります。足す前に result.Data.Bindings（TrackName）と result.Timeline.GetOutputTracks()（名前）で、すでに足してあるかを確認してください
互換Editor 契約として固定されています。メンバー・列挙値は追加のみで、削除や改名は CHANGELOG.md に記載されます

外部パッケージのカットシーン・マーカー（ICutsceneMarker）

Timeline の Marker 派生クラスに ICutsceneMarker を実装すると、カットシーンの再生位置がそのマーカーの時刻を跨いだ瞬間に Fire が呼ばれます。D-Drive の Event / Signal / Shake / Haptic マーカーと同じ規則で、外部パッケージ（DDrive.Runtime を参照するアセンブリ）が自前のマーカーを足せます。

using DDrive.Runtime.Cutscene;
using UnityEngine.Timeline;

public sealed class MyMarker : Marker, ICutsceneMarker
{
    public void Fire(in CutsceneMarkerContext context)
    {
        // context.MarkerTime  = マーカーの時刻（秒）
        // context.Elapsed     = 発火時点の再生位置（秒、MarkerTime 以上）
        // context.Director    = 再生中の PlayableDirector
        // context.Handle      = 再生中のカットシーンのハンドル（Edit Mode のプレビューでは無効）
        // context.IsEditPreview = Edit Mode の Timeline ウィンドウ再生か
    }
}
項目内容
呼ばれるとき再生位置が時刻を跨いだ Tick で 1 回。最初から再生したとき（開始位置 0）は、ちょうど 0 秒に置いたマーカーも最初の Tick で呼ばれます。ネットワーク再生（Cosmetic）の受信側も、新規の再生開始（開始位置が 0.5 秒以内）なら通信遅延の間に過ぎたマーカー（0 秒を含む）が最初の Tick で 1 回ずつ呼ばれ、送信側と同じ回数になります。巻き戻しても再発火しません。1 Tick で複数跨いだら時刻順に呼ばれます。Timeline 上端のマーカー領域に置いたマーカーも対象です
呼ばれないときSeek / Skip・ネットワークの途中参加（Late Join。開始位置が 0.5 秒を超える受信）で跨いだ分（開始位置ちょうどを含む）は無音。Edit Mode ではスクラブ（Timeline ウィンドウが再生中でない）・途中からの再生開始位置まで・巻き戻しも無音（再生を始める直前の位置が先頭（0 秒）のときは 0 秒のマーカーも呼ばれます）。Fire の中でカットシーンを止めたときは、同じ Tick の残りのマーカーは呼ばれません（他のカットシーンを止めても、再生中のカットシーンの進行は乱れません）。CutsceneDirectorContext.FireEnabled が false の間も呼ばれません
例外マーカーごとに捕まえて Console に出し、他のマーカーと再生は続きます
ネットワーク呼び出しは各クライアントのローカル処理で、ネットワークには流れません（Cosmetic のカットシーンなら各クライアントが同じ時刻に自分で呼びます）。全員で同じ結果が要る処理は、外部側で同期してください
実装の注意Fire は Tick 内で呼ばれるので、割り当て・LINQ・クロージャを避けてください。Marker は ScriptableObject なので、Reset など Unity が特別扱いするメソッド名を static で定義しないでください。ICutsceneMarker を実装しない Marker は無視されます
互換ICutsceneMarker / CutsceneMarkerContext は公開 API で、追加のみです（欄の追加は末尾）。挙動は外部拡張の契約（E-20）としてテストで固定されています

取り込みルールの外部拡張（IImportRuleHandler / IImportRuleFolderOptOut）

SourceAssets/<種別>/ への配置で Data を作る取り込み（ImportRule）を、外部パッケージから拡張できます。DDrive.Editor を参照するエディタ用コードに書きます。どちらも TypeCache で自動発見されます（public な型と public な引数なしコンストラクタが必要。登録コードは不要。名前が DDrive.Tests で始まるアセンブリは除外）。

using DDrive.Editor.Import;

// ハンドラを持たず「SourceAssets/MyKind/ は自分が管理するので案内しないで」とだけ宣言する
public sealed class MyFolderOptOut : IImportRuleFolderOptOut
{
    public IEnumerable<string> FolderNames => new[] { "MyKind" };
}

// D-Drive の既存の種別（AssetType）の Data を作るハンドラを足す
public sealed class MyHandler : IImportRuleHandler
{
    public string TypeFolder => "MyKind";            // SourceAssets/MyKind/<カテゴリ>/
    public AssetType Target => AssetType.Se;
    public Type DataType => typeof(SeData);
    public string[] Extensions => new[] { ".wav" };   // 小文字・ドット付き
    public string IdentifierFallback => "My";
    public UnityEngine.Object LoadSource(string assetPath) => AssetDatabase.LoadAssetAtPath<AudioClip>(assetPath);
    public void Configure(AssetDataBase data, UnityEngine.Object source, string assetPath) { ((SeData)data).Clips = new[] { (AudioClip)source }; }
}
項目内容
順序外部ハンドラは組み込みの 9 種別の後ろに、型のフルネーム順で並びます。組み込みの動作は変わりません
競合組み込みの種別フォルダ（Se など）や D-Drive が別経路で使うフォルダ（Shaders / Data / Samples / Cutscene）と同じ名前は、警告を 1 回出して無視されます（組み込み優先）。外部ハンドラ同士が同じ名前なら型名の早い方が使われます
宣言の規則FolderNames の空文字・null・空白・区切り文字入り・重複は無視されます。ハンドラの TypeFolder が空の間は名乗っていない扱いです
例外ハンドラの LoadSource / Configure の例外は Console に出して、そのファイルだけ Data を作らずに続行します
キャッシュ発見結果はドメインリロードまで使い回されます（取り込みのたびに走査しません）
制約ハンドラが作れる Data は D-Drive の既存の AssetType に限ります（ファイル名・フォルダ・ID の決まりは既存種別のものを使うため）
互換Editor 契約として固定されています。メンバーは追加のみです

変換表・テクスチャ規則の提供口（IShaderConversionTableProvider / ITextureImportRuleProvider）

他パッケージが持つシェーダー変換表と、テクスチャのインポート規則（命名 → 設定）を、プロジェクトの Assets/ に置かずに D-Drive へ渡せます。どちらも TypeCache で自動発見されます（public な型と引数なしコンストラクタ）。

using DDrive.Editor.Materials;

public sealed class MyTables : IShaderConversionTableProvider
{
    public IEnumerable<ShaderConversionTable> GetTables()
        => new[] { AssetDatabase.LoadAssetAtPath<ShaderConversionTable>("Packages/com.example.toon/Editor/ToonConversion.asset") };
}

public sealed class MyTextureRules : ITextureImportRuleProvider
{
    public IEnumerable<TextureImportProfile.Rule> GetRules()
    {
        yield return new TextureImportProfile.Rule
        {
            Name = "ToonMask", Match = TextureImportProfile.MatchKind.Suffix, Pattern = "_ToonMask",
            Type = TextureImporterType.Default, SRgb = false, Mipmaps = true,
            Compression = TextureImporterCompression.CompressedHQ,
        };
    }
}
項目内容
変換表の優先順位マテリアル変換ウィンドウは Assets/ の表 → 外部が返した表 → D-Drive 同梱の表の順に探します。同じ変換元・変換先の表が複数あれば先に並んだ表が使われます。GetTables() は表を集め直すたびに呼ばれます
規則の評価位置外部の規則は Profile（TextureImportProfile）の Rules の前に評価されます（T_ 接頭辞の規則より先に効きます）。Postprocessor・Validation・TextureData・ImportRule・Maya 取り込みのすべてが同じ判定を通ります。対象パス（IncludePathContains）は Profile で決まります
プロジェクトの上書きProfile の Rules に、外部規則と同じ条件（Match の種類と Pattern。大文字小文字は区別しない）の規則があれば、そちらが優先され外部規則は使われません。条件が違う規則は上書きされません
呼ばれる回数GetRules() はドメインリロードごとに 1 回です（テクスチャごとには呼びません）
例外提供口ごとに捕まえて Console に出し、他の提供口は有効なままです
互換Editor 契約として固定されています。メンバーは追加のみです

現在の視点カメラ（ViewCamera / IViewProvider）

「今の視点」（位置・回転・縦画角）を取り出す静的ファサードです。顔の補正やビルボードのように「どこから見られているか」で結果が決まる処理が、Camera.main を直接読まずに済みます。分割画面のように視点が複数あるときは、IViewProvider を登録して視点を差し替えます。名前空間は DDrive.Runtime.Viewing。Manager は無く、DDriveRuntimeBootstrap への配線も要りません。

using DDrive.Runtime.Viewing;

// 取り出す側
if (ViewCamera.TryGetCurrent(subject, out ViewPose pose))   // subject = 補正をかける対象の Transform（null 可）
{
    // pose.Position / pose.Rotation（ワールド）、pose.VerticalFovDegrees（度）、pose.Source、pose.Camera
}

// 差し替える側（分割画面など）
public sealed class SplitScreenViews : IViewProvider
{
    public bool TryGetView(Transform subject, out ViewPose pose)
    {
        // subject を担当するプレイヤーのカメラが見つかれば true を返す
        // pose = new ViewPose(cam.transform.position, cam.transform.rotation, cam.fieldOfView, ViewSource.Override, cam);
        pose = default;
        return false;   // 担当でなければ false（次のプロバイダ / Camera.main へ進む）
    }
}
ViewCamera.Register(provider, priority: 10);   // 優先度が高いほど先に問い合わせる。解除は ViewCamera.Unregister(provider)
項目内容
解決順登録された IViewProvider（優先度の降順、同じ優先度は登録順）→ カットシーンが Camera.main を駆動中ならその現在の姿勢（Source = Cutscene）→ Camera.main（Source = MainCamera）→ どれも無ければ false（Source = None。警告は出しません）
値Unity のワールド座標（m / Y-up / 左手）の位置・回転と、縦画角（度、Camera.fieldOfView そのまま）。単位・座標系の変換はしません。正射影カメラでも fieldOfView の値をそのまま返します（正射影の大きさは返しません）。物理カメラ（焦点距離）の値は返しません
呼ぶタイミングカットシーン中のカメラは DDriveCutsceneCameraApplier（実行順 DDriveCutsceneCameraApplier.ExecutionOrder = 1000）が LateUpdate で書きます。そのフレームのカット姿勢が欲しいときは、LateUpdate で、実行順が 1000 より後のコンポーネントから呼んでください。それより前（Update や実行順 1000 未満）で呼ぶと、1 フレーム前の姿勢です。ブレンド中は途中の姿勢がそのまま返ります（ブレンドの割合は返しません）
例外・破棄TryGetView の例外は Console に出して次のプロバイダへ進みます。破棄された MonoBehaviour のプロバイダは飛ばして取り除きます。登録した側は不要になったら Unregister してください（ドメインリロードを無効にした Play Mode でも、Play の開始時に登録は空になります）
性能TryGetCurrent は割り当てなしで、1 フレームに何度呼んでもよい（結果は保持せず、呼んだ時点のカメラの姿勢）
Edit ModeTimeline ウィンドウのスクラブ中は Camera.main に直接書かれるため、Source = MainCamera でその姿勢が返ります
