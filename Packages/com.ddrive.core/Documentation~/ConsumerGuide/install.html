導入手順

最終更新日: 2026-09-20

D-Drive（com.ddrive.core）を、このプロジェクトに初めて導入する手順です。所要時間の目安は 10 分（Unity の再コンパイル待ちを除く）。実行するのはプログラマー・テクニカルアーティストを想定していますが、流れを知っておくとトラブル時に自分でも状況を確認できます。

0. 前提条件

項目要件
Unity6000.3 以上
レンダーパイプラインURP のみ（Built-in / HDRP は非対応）
GitHub アクセスD-Drive のリポジトリは private のため、この PC に GitHub への git 認証（HTTPS の Git 資格情報、または SSH 鍵）が設定されていること
「Assets 直下に新規フォルダを作らない」規約ある場合は手順 3 のセットアップウィザードで「置き場所」を変更する（後述）

1. manifest.json に D-Drive と依存をまとめて追加する

プロジェクトの Packages/manifest.json に、D-Drive 本体(git URL)と、git 配布のため package.json に書けない依存(UniTask・R3)、R3 が使う NuGet パッケージの scoped registry をまとめて追加します。

{
  "scopedRegistries": [
    {
      "name": "Unity NuGet",
      "url": "https://unitynuget-registry.openupm.com",
      "scopes": ["org.nuget"]
    }
  ],
  "dependencies": {
    "com.ddrive.core": "git+https://github.com/wrenchsun/D-Drive.git?path=Packages/com.ddrive.core#v1.0.0",
    "com.cysharp.unitask": "https://github.com/Cysharp/UniTask.git?path=src/UniTask/Assets/Plugins/UniTask#2.5.11",
    "com.cysharp.r3": "https://github.com/Cysharp/R3.git?path=src/R3.Unity/Assets/R3.Unity#1.3.1",
    "org.nuget.r3": "1.3.1"
  }
}

既存の manifest.json にはすでに dependencies（と、あれば scopedRegistries）があるはずなので、上記はそれぞれの中身をマージしてください。

コミットハッシュを直接指定する場合は、省略しない 40 桁のフルコミットハッシュを書く。 タグの無いコミットを指定したいとき（検証目的など）、短縮形（例 #6c65a89）を使うと Package Manager がCould not clone … Make sure […] is a valid branch name, tag or full commit hashで解決に失敗します。通常はタグ（#v1.0.0 等）を使ってください。

SSH 鍵で GitHub に認証する環境では、com.ddrive.core の値を git+ssh://git@github.com/wrenchsun/D-Drive.git?path=Packages/com.ddrive.core#v1.0.0 形式に置き換えても参照できます(挙動は同じ)。まず git+https 形式を試し、環境が SSH 鍵運用のときだけ git+ssh に切り替えてください。

NGO（マルチプレイ、com.unity.netcode.gameobjects）は任意です。使う場合だけ、下記「依存関係」表のとおり別途 manifest.json に追加してください（D-Drive の NGO 連携コードは別アセンブリ DDrive.Runtime.Ngo に分離されており、導入しなくても D-Drive 本体のコンパイルには影響しません）。

依存関係

種別パッケージ扱い
レジストリ配布（自動解決）com.unity.addressables / com.unity.inputsystem / com.unity.render-pipelines.universal（URP）/ com.unity.timeline / com.unity.nuget.newtonsoft-json / com.unity.uguiPackage Manager が package.json の依存として自動解決する。URP と Timeline は DDrive.Runtime の必須依存（ゲーム実行時にも必要）
git 配布（手順 1 でまとめて追加）com.cysharp.unitask / com.cysharp.r3 + scoped registry org.nuget.r3package.json に書けない種類の依存。書き忘れてもセットアップウィザードの「1. 依存パッケージ」が不足を検出し「追加」ボタンで導入できる
任意（NGO を使う場合のみ）com.unity.netcode.gameobjects導入すると DDrive.Runtime.Ngo が自動でコンパイル対象になる。Host/Client 全員が同じ版を導入すること
開発専用（持ち込み先には不要）Unity MCP 各種、D-Drive のテスト用パッケージパッケージには含まれない。Unity の操作は持ち込み先自身の環境に従う

2. Unity を開く

Package Manager が git URL をすべて解決し、レジストリ配布の依存も自動解決します。ここまでで D-Drive の全アセンブリがコンパイルできる状態になります。コンパイルエラーが出た場合は、依存の追加漏れ（手順 1）か、次に説明するステップの前提（DDrive.Generated を参照するコードを先に置いていないか等）を確認してください。

3. セットアップウィザードを実行する

Unity のメニューから Tools > D-Drive > Setup > セットアップウィザード を開き、上から順に確認・適用します。各ステップには「再検査」ボタンがあり、直した後にその場で確認できます。

  1. 1. 依存パッケージ: 手順 1 で追加済みのため通常は「OK」。欠けていれば「追加」ボタンで導入する
  2. 2. ProjectSettings: レンダーパイプライン（URP）・入力方式（Input System）・API 互換レベル（.NET Standard 2.1）を検査する。自動では変更しない項目もある（「Project Settings > Player を開く」ボタンで手動設定に案内される）
  3. 3. 置き場所: D-Drive が作るデータ（GameData/Generated/SourceAssets/Specs）の置き場所を選ぶ。「適用」ボタンで確定する。3 通り:
    • 既定のまま（Assets/GameData 等、Assets 直下）
    • 1 つの親フォルダ配下にまとめる（例 Assets/_Project/DDrive）。「Assets 直下に新規フォルダを作らない」規約があるプロジェクトはこちらを選ぶ
    • 個別に指定する
  4. 4. 既定フォルダ・設定の生成: 「生成」ボタン（SourceAssets/UiLayerSettings/DDriveSpecSettings/カタログ + ID/Tuning 再生成をまとめて実行）
  5. 5. Addressables 同期: AddressableAssetSettings が無ければ「初期化」ボタンで作成する。作成直後に空カタログが自動で Addressables に登録されるが、念のため「全カタログ・Data を今すぐ同期する」ボタンでいつでもまとめて同期できる。既定アセット名にスペースが入っている場合（Unity Addressables の既定生成物 Default Local Group/Packed Assets 等）は「スペースを含む既定アセット名をリネーム」ボタンで解消する
  6. 6. 起動オブジェクト: 「配置(またはカタログを再収集)」ボタンでシーンに起動オブジェクト（DDriveRuntimeBootstrap）を置く
  7. 7. テストを有効化する(既定 OFF): D-Drive 自身のテストをこのプロジェクトの Test Runner で実行できるようにするかどうか。通常のゲーム開発では ON にする必要はない（詳細は運用方法「テストの有効化」）
  8. 8. エージェント向けスキル: 「.claude/skills/ddrive-consumer へコピー」ボタン（AI エージェントを使う場合）
  9. 9. 完了チェック: 「すべて再検査」で上記の状態を一覧確認し、「Validation > Run All を実行」で自動チェックもあわせて実行できる
✔ ここまでで OK なライン: ウィザードの各ステップがすべて「OK」表示、かつ Tools > D-Drive > Validation > Run All で Error が 0 件。

4. SE を 1 件登録して試聴する

Tools > D-Drive > AssetBrowser で新規 SE アセットを作成し、音源ファイルを割り当てて試聴します（Unity の操作自体はこのプロジェクトの環境・MCP 構成に従ってください。D-Drive 独自の操作手順はありません）。

5. Play Mode で ID を再生する

登録した SE の ID 定数を使って 1 行で再生できます。

using DDrive.Generated;
using DDrive.Runtime.Audio;

Audio.PlaySe(SEID.X);

シーンに起動オブジェクト（DDriveRuntimeBootstrap）が置かれていることが前提です（手順 3-6 で配置済み）。

✔ 導入完了の確認ライン: Play Mode で上記の 1 行が例外なく実行され、登録した SE の音が鳴る。Validation > Run All が Error 0 件。

つまずきポイント

Package Manager がタグ・コミットハッシュを解決できない: 短縮 SHA を使っていないか確認する（フル 40 桁が必要。上記「1」参照）。
Validation にカタログ未登録の Error が出る: セットアップウィザード「5. Addressables 同期」の「全カタログ・Data を今すぐ同期する」ボタンを押す。
Validation に「Mixer が未割当」等、URP 関連の Warning/Error が出る: ウィザードは URP アセットの生成・割り当てまでは行いません（検査のみ）。空プロジェクトで URP をまだ使っていない場合は、Assets > Create > Rendering > URP Asset (with Universal Renderer) で作成し、Project Settings > Graphics/Quality に割り当ててください。
生成定数（SEID.Xxx 等）が見つからない: Tools > D-Drive > Generate > Regenerate Asset IDs を実行する。DDrive.Generated を参照するコード（ランタイム・テスト）は、この再生成が終わったあとに追加すること（先に置くとコンパイルエラーでセットアップ自体が止まる）。
