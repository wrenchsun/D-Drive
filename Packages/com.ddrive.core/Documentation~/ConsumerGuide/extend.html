拡張の作り方

最終更新日: 2026-10-16

このプロジェクトだけで使う新しい種別（Data + Manager + 専用エディター …）を、D-Drive を更新せずに足す手順です。D-Drive のパッケージ（com.ddrive.core）には何も書き足しません。所要時間の目安は 8 分。

1. 雛形をコピーする

  1. Package Manager で D-Drive を選び、Samples タブの Extension Template の Import を押す（または Packages/com.ddrive.core/Samples~/ExtensionTemplate/ をフォルダごとコピー）。
  2. 入ったフォルダを Assets/_Project/DDriveExtensions/<Name>/（例: LightCue）へ移す。Runtime/ と Editor/ に asmdef が 1 つずつ入っている。

2. 名前を付け替える

雛形の種別名は Sample（接頭辞 SMP、ID 定数クラス SMPID）です。種別キー・接頭辞・ID 定数クラス名・フォルダ・カタログ名・クラス名とファイル名・asmdef 名を自分の名前に変えます。どこをどう変えるかは、コピーしたフォルダの README.md の表にあります。ScriptableObject の Data は「クラス名 = ファイル名」にします。

3. 確かめる

  1. コンパイルが通ることを確認し、Tools > D-Drive > Validation > Run All を 1 回（Error 0）。
  2. Tools > D-Drive > Generate > Regenerate Asset IDs で ID 定数（<Name>ID.Xxx）を生成。
  3. Tools > D-Drive > Asset Browser →「＋ 新規作成」に自分の種別が出る。作った Data をダブルクリック → 専用エディターが開く → ▶ で自分の Manager が動く。
  4. 空状態の「サンプルを作る」で、サンプルの Data が命名規則どおり（SMP_…）に作られ、カタログと Addressables に登録される。

4. D-Drive を更新するとき

D-Drive の更新（更新方法）で壊れないのは、公開 API だけです（互換性ポリシーで「追加のみ」と決まっています）。雛形が使っているのは、すべてその公開 API（IAssetKindProvider / IDDriveModule / UxEditorWindow<T> / ISampleProvider ほか）です。internal の型や、D-Drive のソースを直接書き換えるやり方は、更新で上書き・破損するので避けてください。更新後は Validation > Run All で自分の種別の検査（IKindValidator）も通ることを確認します。

5. 困ったとき

  • 種別が AssetBrowser に出ない: IAssetKindProvider が public で引数なしコンストラクタか、KindKey が空でないか、Data の [AssetIdDefinition] に KindKey があるか。
  • ▶ が動かない: IDDriveModule が public か、Console に「IDDriveModule … failed to start」の警告が無いか。
  • 詳しい仕組み・拡張点の一覧: D-Drive の ProgrammerManual「新しい種別を追加する」（docs/ProgrammerManual/extending.html）。
