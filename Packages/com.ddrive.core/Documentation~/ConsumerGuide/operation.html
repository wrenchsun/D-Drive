運用方法

最終更新日: 2026-09-20

導入（導入手順）が終わったあと、このプロジェクトで D-Drive を日常的に使い続けるための運用ノウハウです。所要時間の目安は 10 分。

1. 日常の Validation > Run All

Tools > D-Drive > Validation > Run All（CI からは -executeMethod DDrive.Editor.CI.ValidateAll）が Data・カタログ・Addressables 登録・ProjectSettings 等をまとめて検査します。

  • Error（赤）: 実行時に Placeholder になる・コンパイルが壊れる等、実害のある問題。CI ではこれを fail 条件にする
  • Warning（黄）: すぐには困らないが直したほうがよい項目。DD-SETUP- で始まる警告はセットアップウィザードの該当ステップを開くと直せる

D-Drive の更新直後は新しい Warning が増えることがあります（仕様変更の周知が目的）。Error は更新直後には増えない設計（2 段階ルール）なので、更新した直後に Error が増えた場合はまず「更新手順を最後まで終えたか」を確認してください。

2. ID・調整値の再生成

Assets/Generated/（または DDrive.Generated.asmdef を出力する設定を選んだ場合はそのフォルダ）にある AssetIds.g.cs・Tuning.g.cs は生成物です。手で編集しないでください。

  • Tools > D-Drive > Generate > Regenerate Asset IDs: アセットを新規作成・削除したあとや、生成定数が古いと感じたときに実行する
  • Tools > D-Drive > Generate > Regenerate Tuning Keys: 調整値（Tuning）のキー一覧を作り直す

ID 定数（SEID.X 等）が未登録の状態で Play/Spawn しても例外にはならず、警告ログ + Placeholder（無音・代役の見た目）で処理が継続します。デザイナー側の作業が未完了なだけの可能性が高いので、慌てて実装を変える必要はありません。

3. Addressables 同期

新しい種別のアセットを初めて作ったときや、カタログを作った直後は Addressables への登録が必要です。

  • Tools > D-Drive > Update > 更新ウィンドウ の「Addressables 登録を同期」
  • またはセットアップウィザード「5. Addressables 同期」の「全カタログ・Data を今すぐ同期する」ボタン（同じ処理）

Asset Browser 経由でアセットを作成した場合は、作成時に自動で登録されます。まとめて同期が必要になるのは、空カタログを作っただけの状態や、Addressables を初期化し直した直後です。

4. CI テンプレの組み込み

このプロジェクトの CI に D-Drive の互換性・品質チェックを組み込みたい場合は、パッケージの Tools~/CI/（Unity から見えない配布用フォルダ）にあるテンプレートを使います。

  1. Tools~/CI/run-ddrive-ci.cmd を、このプロジェクトの Tools/CI/（無ければ好きな場所）へコピーする
  2. Tools~/CI/ddrive-ci.yml を、このプロジェクトの .github/workflows/ へコピーする
  3. runs-on のラベル・Unity Editor のパス等を、このプロジェクトの runner 構成に合わせて書き換える

実行される内容は、run-ddrive-ci.cmd/ddrive-ci.yml のどちらも次の 4 段を順に実行し、途中で失敗したら止まります。

  1. DDrive.Editor.CI.MigrateCheck — 未適用のデータマイグレーションが無いか
  2. DDrive.Editor.CI.ValidateAll — Validation の Error が無いか
  3. DDrive.Editor.CI.RegenerateIds + git diff --exit-code — ID/調整値の生成コードに未コミットの差分が出ないか
  4. EditMode / PlayMode テスト（このプロジェクトの Test Runner に登録されているテストを実行する。D-Drive 自身のテストも含めたい場合は下記「テストの有効化」を ON にする）
既存の Unity 用 CI が無いプロジェクトの場合: ddrive-ci.yml は既存のワークフローに手を加えて差し込むのではなく、新しいワークフローとして追加してください。self-hosted runner を使う場合はラベルで指定し（他プロジェクトの runner に誤って割り当てない）、push のトリガーは Assets/**・Packages/**・ProjectSettings/** にパスを絞ってドキュメントだけの変更では動かさないようにします。CHANGELOG ガード・Performance テスト・NetCheck（複数クライアント自動テスト）は D-Drive の開発リポジトリ専用の検査のため、このテンプレートには含まれていません。

5. 命名規則との付き合い方

Addressables の既定名リネーム

Unity Addressables が自動生成するグループ・スキーマ名（Default Local Group・Packed Assets 等）には既定でスペースが含まれます。プロジェクトの CI/Hygiene チェックが「ファイル名にスペースを含めない」規約を持つ場合、これに抵触することがあります。セットアップウィザード「5. Addressables 同期」の「スペースを含む既定アセット名をリネーム」ボタン、または ProjectSetupValidator の Warning（DD-SETUP-ADDR-NAME-SPACE）の修正アクションで解消できます（新規初期化直後は自動でリネームされます。既存プロジェクトで人が付けた名前は勝手に変更しません）。

D-Drive が管理するデータの置き場所

Assets/GameData/・Assets/Generated/・Assets/SourceAssets/（または導入時に選んだ置き場所プリセットの下）は D-Drive のツールが管理する領域です。人が手でファイルを移動・リネームしないでください（ID は GUID 由来で不変ですが、ツールの命名規約・カタログ整合性が崩れます）。「Assets 直下に新規フォルダを作らない」規約があるプロジェクトは、導入時にセットアップウィザードの「置き場所」で「1 つの親フォルダ配下にまとめる」を選んでいるはずです（未選択の場合は再度ウィザードの「3. 置き場所」から変更できます）。

6. テストの有効化

D-Drive 自身が持つテスト（EditMode/PlayMode）を、このプロジェクトの Test Runner で実行できるようにするかどうかの設定です。既定は OFF（実行できない状態）で、通常のゲーム開発では ON にする必要はありません。プロジェクトの CI に D-Drive の自動テストも含めたい場合にだけ ON にします。

  • ON にする: セットアップウィザードまたは更新ウィンドウの「テストを有効化する」。内部で manifest.json の testables に com.ddrive.core が追加される
  • OFF に戻す: 同じ項目をもう一度操作する

7. AI エージェント向けスキル

Claude Code 等の AI エージェントに D-Drive まわりの作業を頼む場合は、次の 2 つを参照させてください。

  • Documentation~/AGENTS_CONSUMER.md: 禁止事項（Data のテキスト編集禁止・禁止 API・パッケージ改造禁止 等）と作業規約
  • Documentation~/skills/ddrive-consumer/SKILL.md: ID 経由の利用パターン・アセットの作り方・Validation の読み方・更新手順・Presentation/Cutscene の使い分け

セットアップウィザード・更新ウィンドウの「エージェント向けスキルを更新」ボタンで、このプロジェクトの .claude/skills/ddrive-consumer/ へ最新版がコピーされます。

8. 困ったときの見方

  1. まず Tools > D-Drive > Validation > Run All を実行し、表示される Error/Warning の説明文に従う
  2. 典型的な症状と対処は下表を参照する
  3. それでも解決しない場合は、開発リポジトリ（github.com/wrenchsun/D-Drive）へ Issue を立てるか、CHANGELOG.md の該当版の記述を確認する

よくある症状と対処

症状典型的な原因対処
カタログ未登録: '...'(ID 0x...)がどのカタログにもありません（Error）Asset Browser 以外の方法でアセットを作成したAsset Browser 経由で作り直すか、Regenerate Asset IDs を実行してカタログ登録を揃える
Addressables 未登録: '...' がグループに入っていません（Error）Addressables への同期を実行していない上記「3. Addressables 同期」を実行する
Flags.Load が Preload ではありません（Error）同期解決 API（Audio・Vfx・Anim・Presentation 等）の Data で Load が Preload 以外対象 Data の Inspector で Flags.Load を Preload に変更する
禁止 API の検出（ForbiddenApiScanner）ゲームコードで Instantiate/Resources.Load/AudioSource.Play を直接呼んでいるD-Drive の静的ファサード（Prefabs/Audio 等）経由に置き換える
DD-SETUP-*（Warning）依存パッケージ・ProjectSettings・置き場所等の不足セットアップウィザードの該当ステップの「直す」を実行する
DD-SETUP-UPDATE-PENDING（Warning）更新がまだ適用されていない更新方法の「更新を適用」を実行する
DD-SCHEMA-OUTDATED（Warning）Data の形式が古い更新ウィンドウの「更新を適用」がマイグレーションも実行するので、通常はこの手順で解消する
DD-SETUP-EMBEDDED-MODIFIED（Warning）パッケージが埋め込み（改造可能な状態）になっている通常の git URL 参照に戻す。どうしても改造が必要な場合は開発リポジトリへの提案を検討する
Console に [DDrive] Unregistered AssetId 0x{id:X} resolved to Placeholder.未登録 ID を Play/Spawn した（例外にはならない）デザイナー側の作業がまだ完了していないだけの可能性が高い。慌てて実装を変えない
