Handle・イベント・完了待ち

D-Drive の各種ファサード（Vfx / Anim / Presentation / Ui …）は、再生中の実体を直接返さず Handle という軽量な参照を返します。Handle の仕組み・世代（Generation）による安全性・種別ごとの完了待ち方法をまとめて説明します。個別の種別の API シグネチャは 演出（Presentation）と Anchor・Canvas / UI Tween や他ページを参照してください。

Handle<TMarker> の仕組み

Foundation/Handle/Handle.cs:7-33。GC alloc 0 の readonly struct で、Index（台帳上の位置）と Generation（世代）の 2 つの int だけを持ちます。

public readonly struct Handle<TMarker> : IEquatable<Handle<TMarker>>
{
    public readonly int Index;
    public readonly int Generation;

    public static readonly Handle<TMarker> Invalid;          // (-1, 0)
    public static Handle<TMarker> Sentinel(int tag);         // 負のインデックス(tag ごとに異なる値、tag >= 0)
}

有効性は Handle 自身では判定せず、生成元の InstanceStore<TMarker, TInstance>（Foundation/Handle/InstanceStore.cs）に問い合わせて判定します。Sentinel(tag) は Manager の台帳に属さない「擬似ハンドル」用です（InstanceStore は負のインデックスを警告なしで無効扱いするため、エディタのプレハブモードその場再生のような独自管理の再生を同じ Handle 型で扱うのに使います）。

マーカー型による種別の型安全な分離

TMarker には中身の無い struct タグ（VfxMarker / SeMarker / AnimMarker / PresentationMarker / CanvasMarker / UiTweenMarker / AnchorGroupMarker …)を渡します。これにより Handle<VfxMarker> と Handle<SeMarker> はまったく別の型になり、コンパイル時に「VFX の Handle を誤って Audio.Stop に渡す」といったミスを防げます。AssetId<TMarker>（種別ごとの ID 型）も同じマーカー型を使い回しており、ID と Handle の対応も型で保証されます。

世代（Generation）— なぜ必要か

InstanceStore は配列 + フリーリストで Instance を管理します（Foundation/Handle/InstanceStore.cs:9-107）。ある Instance が終了すると、そのスロットのインデックスはすぐに次の Add で再利用されます。もし有効性を「そのインデックスに何か入っているか」だけで判定すると、古い Handle が別の(たまたま同じスロットに入った)新しい Instance を誤って操作してしまうという事故が起きます（いわゆる ABA 問題）。

public bool TryGet(Handle<TMarker> handle, out TInstance instance)
{
    if (handle.Index >= 0 && handle.Index < _count &&
        _generations[handle.Index] == handle.Generation &&   // ← 世代が一致しないと無効
        _items[handle.Index] != null)
    { ... }
}

public void Remove(Handle<TMarker> handle)
{
    ...
    _items[handle.Index] = null;
    _generations[handle.Index]++;      // ← 破棄のたびに世代を進める
    _freeIndices.Push(handle.Index);
}

Remove（Instance の破棄）のたびにそのスロットの世代を 1 つ進めるため、Handle を保持したまま対象が終了した後にその Handle を使っても、スロットが再利用されて新しい Instance が入っていた場合はもちろん、まだ何も入っていない場合でも世代が一致せず、常に「無効」として扱われます。誤って他人の Instance を触ることはありません。なお _generations[index] == 0 は「未初期化(default(Handle<T>))」と衝突しないよう、実際の世代は必ず 1 から始まります。

無効な Handle を操作するとどうなるか

D-Drive は例外で止めません（TL;DR §4）。無効な Handle への操作は次のように扱われます。

メソッド挙動
TryGet / IsValidfalse を返す。Index が範囲内なのに世代不一致などの場合は InvalidAccessCount をカウントし、開発ビルド/エディタでは Debug.LogWarning を出す(Stop/Signal のような「操作」系メソッドが内部で使う)
IsValidSilent警告・カウント無しで false を返す。「まだ再生中か」のポーリング(IsPlaying や WaitAsync の完了判定)用。終了済み Handle への問い合わせは正常な使い方なので警告にしない

つまり Vfx.Stop(oldHandle) のように終了済みの Handle へ操作を呼んでも安全に無視されますが、開発ビルドではコンソールに警告が出る点に注意してください。一方で Vfx.IsPlaying(oldHandle) は何も警告せず単に false を返すので、毎フレームのポーリングに使っても問題ありません。

PresentationHandle — 専用ラッパー

Runtime/Presentation/PresentationHandle.cs:13-55。他種別は「Handle<TMarker> + 拡張メソッド」で済ませていますが、Presentation は Signal/Cancel/Pause 等の「制御」がここに集約されるため専用の readonly struct になっています。中身は Handle<PresentationMarker> 1 個だけで GC alloc 0、実体はすべて Presentation 静的ファサード経由で PresentationManager へ委譲します。

public readonly struct PresentationHandle : IEquatable<PresentationHandle>
{
    public readonly Handle<PresentationMarker> Raw;
    public static readonly PresentationHandle Invalid;

    public bool IsPlaying { get; }
    public float NormalizedTime { get; }        // 0..1。無効なら -1

    public void Signal(string key);
    public void Cancel();
    public void Pause();
    public void Resume();
    public void SetSpeed(float speed);
    public void Seek(float time);

    public Observable<Unit> OnCompleted { get; }
    public Observable<Unit> OnCancelled { get; }
    public Observable<string> OnMarker { get; }
    public Observable<PresentationTrack> OnTrackFired { get; }

    public UniTask WaitAsync(CancellationToken ct = default);
}

非対称: R3 イベントを持つのは Presentation だけ

他の種別(Vfx/Anim/Se/Canvas 等)には R3 の Observable がありません。 完了待ちは IsPlaying(h) のポーリング（毎フレーム、または await UniTask.WaitUntil(() => !h.IsPlaying()) のような形)になります。R3 は 5-1 で Presentation 用に導入されたばかりで、他種別への展開はまだ行われていません。

例外は Ui.OnSignal(key, cb)（Canvas / UI Tween参照）ですが、これも R3 の Observable ではなく、単なる Action<SignalArgs> 購読 + IDisposable です。まとめると：

種別完了・イベントの受け取り方
PresentationR3 Observable<T>(OnCompleted/OnCancelled/OnMarker/OnTrackFired) + UniTask WaitAsync
Ui(Canvas)OnSignal(key, Action<SignalArgs>) → IDisposable(R3 ではない素の購読)。開閉待ちは OpenAsync/CloseAsync の UniTask
UiTween(UiFx)IsPlaying ポーリング、または UniTask WaitAsync(h)(内部は UniTaskCompletionSource。ポーリングではない)
Vfx / Anim / Se / Prefab などIsPlaying ポーリングのみ

Bind 前・未 Bind の Observable 系プロパティは、購読しても何も流れてこない Observable.Empty<T>() を返します（例外にしない no-op 原則。Presentation.OnCompleted 等の実装を参照）。

購読の後始末

Subscribe の戻り値（IDisposable）を捨てると、そのオブジェクトが破棄されても購読が残り続け、破棄済みの対象を参照し続けるリークになります。D-Drive 内の実例（Editor/Presentation/PresentationEditorWindow.cs:43-46, 363-370）は、フィールドで保持してまとめて破棄するパターンです。

private IDisposable _subMarker;
private IDisposable _subCompleted;

private void SubscribeToCurrent()
{
    _subMarker = _preview.OnMarker.Subscribe(name => AppendLog($"Marker: {name}"));
    _subCompleted = _preview.OnCompleted.Subscribe(_ => AppendLog("● 完了"));
}

private void DisposeSubscriptions()
{
    _subMarker?.Dispose();
    _subMarker = null;
    _subCompleted?.Dispose();
    _subCompleted = null;
}

DisposeSubscriptions() は Close/StopPreview など「この購読が要らなくなるタイミング」で必ず呼びます。スコープが 1 メソッド内で完結する場合は using var で自動破棄するほうが簡潔です（テストコード Tests/Editor/ScenePresentationPreviewDriverTests.cs:75 の実例）。

using var sub = handle.OnMarker.Subscribe(name => received.Add(name));
// このスコープを抜けると自動で Dispose される
void Play()
{
    _handle = Presentation.Play(id, ctx);
    _handle.OnCompleted.Subscribe(_ => OnAttackFinished());   // 戻り値を捨てている
}
private IDisposable _sub;

void Play()
{
    _handle = Presentation.Play(id, ctx);
    _sub?.Dispose();
    _sub = _handle.OnCompleted.Subscribe(_ => OnAttackFinished());
}

void OnDestroy() => _sub?.Dispose();

R3 には AddTo(this) のような一括破棄の拡張（CompositeDisposable 等)も存在しますが、2026-09-17 時点の D-Drive コード内ではまだ使われていません（フィールド保持 + 明示 Dispose()、または using var が実際のパターンです）。自分のコードで購読が増えてきた場合は R3 の CompositeDisposable を導入して構いません。

種別ごとの Handle 拡張メソッド（ドット記法）

Presentation 以外の種別は Handle<TMarker> 自体を拡張メソッドで飾ることで h.Stop() のようなドット記法を実現しています。実体はすべて対応する静的ファサードへの委譲です。

拡張クラス対象主なメソッド
VfxHandleExtensions（Runtime/Vfx/Vfx.cs:62）Handle<VfxMarker>IsPlaying() Stop() Kill() Move(pos) Attach(t) Detach() SetSpeed(speed) SetParam(label, value)
AnimHandleExtensions（Runtime/Anim/Anim.cs:47）Handle<AnimMarker>IsPlaying() Stop(fade) SetSpeed(speed) NormalizedTime()
PrefabHandleExtensions（Runtime/Prefab/Prefabs.cs:40）Handle<PrefabMarker>Go()（GameObject 取得） GetComponent<T>() Move(pos, rot) HasTag(tag) Despawn() IsValid()
その他Handle<CanvasMarker> / Handle<UiTweenMarker> / Handle<MaterialMarker> / Handle<HapticMarker> / Handle<ShakeMarker>CanvasHandleExtensions / TweenHandleExtensions / MaterialHandleExtensions / HapticHandleExtensions / ShakeHandleExtensions が同じパターンで用意されています
var vfx = Vfx.Spawn(VFXID.Slash, transform);
vfx.Move(newPos);          // Vfx.Move(vfx, newPos) と同じ
if (vfx.IsPlaying()) { ... }

var go = Prefabs.Spawn(PREFABID.Crate, pos, rot);

PresentationHandle だけはこのパターンを使わず、専用 struct にメンバーとして直接生やしている点に注意してください（上の「PresentationHandle」節参照）。
