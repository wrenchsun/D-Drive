はじめに（導入手順・最初の一本）

このページは、D-Drive を初めて触るプログラマーが環境を確認し、ID を1つ鳴らすまでを実際に動かせる形で説明します。Unity の操作（Asset Browser の使い方など）は前提として扱いません。必要なら デザイナーマニュアル: はじめての15分 を先に読んでください。

1. 導入手順（現状ベース、2026-09-17 時点）

1-1. 依存パッケージ

Packages/manifest.json を実際に確認した内容です。バージョンは正確にこのとおりです（CLAUDE.md の「NGO 2.2」という記載は誤りで、実際の manifest の値が正です）。

1-2. 既存プロジェクトに持ち込む場合

2026-09-20 更新: セットアップウィザード（P-6）を実装しました。 Assets/DDrive/ は Packages/com.ddrive.core/（埋め込みパッケージ）へ移設済み（P-5）で、package.json（name: "com.ddrive.core"、version: "1.0.0"）も存在します。持ち込み先で Tools > D-Drive > Setup > セットアップウィザード を開くと、下記の状態をまとめて確認し、ボタン操作だけで直せます。ただし、他プロジェクトから git URL で参照して実際に導入できることの確認（P-11）と消費側ドキュメント一式（P-10）はまだ完了していません。
  1. （推奨、正式な配布手順〔P-9/P-11〕までの暫定） Packages/com.ddrive.core/ フォルダを丸ごとコピー（.meta ファイルも含める。GUID 参照を壊さないため）するか、下記「UPM 化の状況」の git URL 形式で manifest.json に追加する
  2. Tools > D-Drive > Setup > セットアップウィザード を開く。「1. 依存パッケージ」で UniTask / R3 / org.nuget.r3（scoped registry）の不足を検出し、「追加」ボタンで導入できる（NGO はマルチプレイを使う場合のみ任意で導入）
  3. ウィザードの「2. ProjectSettings」で URP アセットの割り当て・Input System の Active Input Handling・API Compatibility Level（.NET Standard 2.1）を確認する（自動変更はしない項目のため、不足があれば案内どおり Project Settings を開いて直す）。同じ検査は ProjectSetupValidator として Validation > Run All にも載る（Code: DD-SETUP-URP / DD-SETUP-INPUT / DD-SETUP-API-LEVEL、いずれも Warning）
  4. ウィザードの「3. 置き場所」で GameData/Generated/SourceAssets/Specs の置き場所を選ぶ（既定のまま／1 つの親フォルダ配下にまとめる／個別指定の 3 通り。DDriveProjectSettings に保存される）。持ち込み先が「Assets 直下に新規フォルダを作らない」規約を持つ場合（MS2026 など）は「1 つの親フォルダ配下」を選ぶ
  5. ウィザードの「4. 既定フォルダ・設定の生成」で GameData/SourceAssets の既定フォルダ・UiLayerSettings・DDriveSpecSettings・各カタログ（空でも可）をまとめて作り、ID/Tuning 定数も再生成する。DDrive.Generated.asmdef を同時出力するかはチェックボックスで選べる（既定 ON。asmdef 付きのゲームコードから生成定数を参照するために必要）
  6. ウィザードの「5. Addressables 同期」で AddressableAssetSettings が無ければ「初期化」する（無いと全 Data が実行時にロードできないと Validation が警告します）
  7. ウィザードの「6. 起動オブジェクト」でシーンに起動オブジェクトを配置する（DDriveRuntimeBootstrap。詳細は bootstrap.html）
  8. Assets/GameData/ はプロジェクト固有の実データ（Data アセット・カタログ・標準プレハブ）なので、そのまま流用するのではなく、持ち込み先で新規に Addressables グループ・カタログを作る運用です（要確認: 実際に「持ち込み」をやった実績は P-11 でまだ検証していません）
UPM 化の状況（2026-09-17 決定 → 2026-09-20 パッケージ化実施、[42_distribution.md]）: Packages/com.ddrive.core/（パッケージ名 com.ddrive.core、表示名 D-Drive）が実在し、このリポジトリ（github.com/wrenchsun/D-Drive、private のまま）を git URL の ?path= 付きで参照する形の配布を想定しています。最初の版は 1.0.0。持ち込み先の manifest.json は次のような 1 行になる想定です（git tag v1.0.0 の打刻は P-9 で行うため、2026-09-20 時点ではこの URL はまだ解決できません）: 
"com.ddrive.core": "git+ssh://git@github.com/wrenchsun/D-Drive.git?path=Packages/com.ddrive.core#v1.0.0"
セットアップウィザード（P-6）は実装済みです。消費側ドキュメント（P-10）・実際に空プロジェクトへ導入する検証（P-11）が完了するまで、上記 1-2 の手順が現行の持ち込み方法です。

1-3. 更新する（2026-09-20 追加、P-8）

D-Drive のバージョンを進めた後（Packages/manifest.json のタグを新しくした後）は、Tools > D-Drive > Update > 更新ウィンドウ を開きます。

  1. 「1. 版と CHANGELOG」で現在の版・前回適用した版（DDriveProjectSettings.LastAppliedVersion）・その間の CHANGELOG の該当節を確認する。「破壊あり」の変更が含まれる場合は警告が出るので、先に docs/migrations/ の移行ガイドを読む
  2. 「2. マイグレーション（プレビュー）」で未適用のデータ移行件数を確認する（この時点では何も変更しない）
  3. 「3. 更新を適用」ボタンを押す。内部では (1) マイグレーション適用 → (2) Regenerate Asset IDs/Regenerate Tuning Keys → (3) Addressables 登録の同期 → (4) Validation > Run All → (5) LastAppliedVersion の更新、の順で実行され、途中の段が失敗したらそこで止まります（それより後の手順・LastAppliedVersion の更新は行われません）
  4. 「4. テストを有効化する」「5. エージェント向けスキルを更新」は上記のセットアップウィザードと同じ項目です

更新をまだ適用していない（LastAppliedVersion が現在の版より古い）状態は Validation > Run All の Warning（DD-SETUP-UPDATE-PENDING）としても検出されます。

Host/Client（マルチプレイ）で D-Drive の版が違う場合の挙動（接続時の ProtocolVersion 照合）は net-api.html「D-Drive の版照合」を参照してください。

2. 最初の一本 — SE を ID だけで鳴らす

デザイナーが登録済みの SE（このリポジトリには実例として SEID.PlayerSlash が既に存在します）を、ID だけで鳴らす最小コードです。実在する API（Packages/com.ddrive.core/Runtime/Audio/Audio.cs の静的ファサード）だけで構成しています。

using DDrive.Generated;
using DDrive.Runtime.Audio;
using UnityEngine;
using UnityEngine.InputSystem;

public class SlashDemo : MonoBehaviour
{
    void Update()
    {
        if (Keyboard.current.spaceKey.wasPressedThisFrame)
            Audio.PlaySe(SEID.PlayerSlash);
    }
}

Audio.PlaySe(SeId id) は Handle<SeMarker> を返します（未使用でも構いません。停止したい場合だけ受け取って Audio.Stop(handle) に渡します）。この 1 行が動くには、シーンに起動オブジェクト（DDriveRuntimeBootstrap）が置かれ、カタログ登録（IsReady）が済んでいる必要があります。詳しくは bootstrap.html、他の種別（VFX・Presentation 等）の呼び出し方は各 API ページを参照してください。

3. つまずきポイント

生成定数（SEID.Xxx 等）が出てこない: まだ Data が作られていない（デザイナー側の作業待ち）か、生成が古いままです。Tools > D-Drive > Generate > Regenerate Asset IDs を実行してください。プログラマー側からアセットが無くても ID だけ先に使いたい場合は、企画側が発注ツール（SpecWeb）に登録すると Placeholder の ID が自動でできる運用です（[docs/34_onboarding.md] §8）。
Play Mode で音が出ない・何も起きない: 代表的な原因は 3 つです。
  1. シーンに DDriveRuntimeBootstrap が無い、またはまだ IsReady になっていない（カタログ登録前は未登録 ID として Placeholder 扱いになります）
  2. 対象の Data が Addressables に登録されていない。Validation を実行すると Tools > D-Drive > Validation > Run All で カタログ未登録: '...'(ID 0x...)がどのカタログにもありません。実行時に解決できず Placeholder になります。 や Addressables 未登録: '...' がグループに入っていません(カタログの Address '...')。実行時にロードできません。 のようなエラーが出ます（Editor/Validation/AddressablesRegistrationValidator.cs）
  3. 同期解決 API（Play/Spawn を同期で呼ぶ種別。Audio・Vfx・Anim・Presentation など、ほぼ全種別）なのに対象 Data の Flags.Load が Preload になっていない。この場合 Flags.Load が Preload ではありません: '...'(...)は Ui.Open 等の同期解決でしか引かれないため、Preload 以外だと実行時に常に Placeholder になります。 という Validation エラーが出ます（[02_core_framework.md] §4）
いずれも例外にはならず、Console に [DDrive] Unregistered AssetId 0x{id:X} resolved to Placeholder.（Foundation/Registry/AssetRegistry.cs）という警告が 1 ID につき 1 回出るだけで処理は継続します（[CLAUDE.md] §0-4「例外で止めない」）。
